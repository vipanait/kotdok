## Что сделано

До этапа у питомца не было места для файлов-документов (паспорт, рецепт, выписка). Теперь владелец на сайте загружает документ из 1-8 фото или одного PDF, видит список и страницы по короткоживущей подписанной ссылке, правит название, вид и дату, удаляет. Файлы лежат в приватном бакете, строки и объекты уходят вместе с документом, питомцем и аккаунтом. Распознавание и согласие на новую редакцию — DOC-2, приложение — DOC-3.

## Решения и отклонения

- **Отказ при `complete` — `400 bad_request`, а не `422`.** Таблица кодов ошибок отображает статус по коду, отдельный код ради одного маршрута не нужен; причина лежит в `details.reason` (`too_many_pages`, `encrypted`, `unsupported_media_type`, `payload_too_large`). Затрагивает только веб-клиент.
- **Лимит 30 документов на питомца закреплён в SQL (`create_pet_document`).** Число 30 продублировано в SQL и в `DOCUMENT_LIMITS.perPet`; расхождение возможно (см. «Незакрытые мелочи»).
- **`complete` отказывает документу старше 2 часов, очистка удаляет `pending` старше 3 часов и не трогает документ, который успел стать `stored`.** По итогам ревью задачи 3.
- **`size_bytes` пишется по фактически скачанному размеру**, а не по заявленному: по сумме этого поля считается порог Selectel.
- **Разбор PDF вынесен в воркер** (`worker_threads`, лимит памяти, 5 с, 64 МБ на декодированный поток) по ревью задачи 2: без этого враждебный PDF мог исчерпать память.
- **Шифрованный PDF 1.5 распознаётся поиском `/Encrypt`**; PDF, который не разбирается, отклоняется как `unsupported_media_type` (отказ в любом случае).
- **Общий клиент получил методы документов и параметр дополнительных признаков.** Веб передаёт `pet-documents`, мобильное приложение не должно заявлять его до DOC-3.
- **Миграции применены к общему локальному стеку вручную** (см. «Непроверенное и риски»).
- **Ограничения интерфейса:** при загрузке нет поля названия (название задаётся правкой, пустое показывается как вид документа); в карточке медкарты нет счётчика; HEIC из Chrome не читается и показывается честным отказом.

## Непроверенное и риски

Что не блокирует приёмку по матрице, но владелец должен знать до слияния:

1. **Миграции применены к общему локальному стеку вручную.** `20261116140000_pet_documents` и `20261116150000_create_pet_document` внесены скриптом на Node с `pg`, строки вставлены в `supabase_migrations.schema_migrations`, потому что `supabase migration up` отказывается работать, когда в стеке применена метка соседней ветки, которой нет в дереве. Команда `migration up` на этой ветке не проверялась. Перед слиянием владелец выполняет `supabase db push` на production, и эти две метки к тому моменту должны быть последними (соседние ветки не должны добавить метку позже; на 16 ноября в дереве до них лежат `20261116120000_safety_ai_answers` и `20261116130000_check_questions`).
2. **Трассировка файлов `pdf-lib` и воркера в `next.config.ts` не проверена на деплое Vercel.** Локальная production-сборка работает, но на Vercel отдельный воркер может не попасть в бандл серверной функции. Первый preview обязан выполнить `POST /api/v1/pets/{id}/documents/{docId}/complete` с PDF. Пока этого не сделано, загрузка PDF на Vercel не подтверждена.
3. **Запрос объёма хранилища для порога Selectel** (решение 20 октября: файлы остаются в Supabase до исчерпания лимита Free или до этапа с документами к визитам; сумма `size_bytes` — метрика порога). Выполнять на production через `supabase db query --linked --project-ref bczseshsgpzulqynvukg` или в SQL-редакторе:

   ```sql
   select count(*)                                    as files,
          count(distinct document_id)                 as documents,
          coalesce(sum(size_bytes), 0)                as bytes,
          round(coalesce(sum(size_bytes), 0) / 1048576.0, 1) as megabytes
   from public.pet_document_files;
   ```

   Поле `size_bytes` пишется по фактически скачанному размеру при `complete` (тест `stores the size that was downloaded, not the one declared`); строки незавершённых документов в `pending` убирает очистка.
4. **Доказательства для DOC-1/04 и DOC-1/06 — интеграционные тесты,** не наблюдение на staging или production. Лимит 31-го документа и суточная очистка в браузере не проверялись.
5. **Доказательство для DOC-1/08 — тест обзора без заголовка `X-Lapka-Features`.** Старая сборка приложения на устройстве не запускалась; терпимое чтение неизвестных разделов закреплено юнит-тестом контракта.
6. **Скриншоты.** Первая проверка (16 ноября) прошла без скриншотов. 17 ноября на сборке `246b8bc` сняты 11 скриншотов: `docs/verification/documents-01/01…11` (01–07 компьютер, 08–11 окно 375 px). Они лежат рядом с отчётом и не коммитятся.
7. **Корневой `npm run typecheck` не проходит из-за окружения** (нет `apps/mobile/node_modules`); типы приложения этим запуском не подтверждены.
