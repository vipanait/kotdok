## Решения и отклонения

1. **Имена без склонения.** По указанию владельца: «Хорошо, что стало лучше», «Стоит показаться врачу», «Покажитесь врачу сегодня». Заголовок хронологии — «Наблюдение: Мурка» (в макете «Наблюдение за Муркой»), подзаголовок повторной проверки — «Повторная проверка · Мурка».
2. **Первое открытие предложения создаёт случай** (`PUT enabled = default_enabled`), как требует план («строка создаётся при первом показе»). Если у питомца уже есть открытый случай, предложение сохраняется выключенным и показывается предупреждение: тихо закрыть чужой случай нельзя.
3. **Время следующего вопроса** считается `followupFireMoment` только в браузере (`useSyncExternalStore`, на сервере `null`) — зона сервера не равна зоне владельца. Остальные даты — в зоне из cookie, как весь кабинет.
4. **«Не найдено» как экран в кабинете с HTTP 200**, а не `notFound()`: так на макете, и текст одинаков для чужого, удалённого и битого id.
5. **`clinic_now`**: в плане есть только заголовок «Нужна клиника сейчас»; текст под ним — существующий утверждённый `urgency.emergency.action`, новых медицинских формулировок не добавлено.
6. **Сводка для врача** не несёт эпизодов в `GET /health/summary`, поэтому блок читает `GET /pets/{id}/health/episodes` и отбирает 6 месяцев на клиенте (см. «API gaps»).
7. «Все случаи · N» ведёт в историю питомца (`/checks?pet=`), где случаи уже сгруппированы: отдельной страницы списка эпизодов нет.
8. FU-08 (фото) не делался.

## Недостающие API и ограничения

1. `GET /pets/{id}/health/summary` не отдаёт перенесённые случаи; веб читает `/health/episodes` отдельно и режет 6 месяцев на клиенте. Печать сводки их включает (блок в потоке страницы), но копирование текста сводки — нет.
2. В `FollowupCaseSummary` нет числа проверок и момента последней проверки (`anchor_at`); для строк истории счёт отметок читается загрузчиком отдельным запросом, «прошло N дней» считается от последней проверки из `FollowupCase.checks`.
3. Нет сервисной функции «случаи по id» — строка истории получает исход из `CheckCaseLink`, этого хватает.
4. «Пора отметить» в строках питомцев на обзоре (есть на макете) не добавлено.
5. Сервер отклоняет повторную проверку закрытого >14 дней случая (409); веб показывает ошибку после отправки, а не прячет плашку заранее — чтобы не дублировать правило.
6. Время в EN пишется «09:00 AM» (формат существующих хелперов), в макете «9:00 AM».
7. Загрузочный экран — существующий `CabinetSkeleton` через `checks/case/loading.tsx`, отдельного скриншота нет.
8. В Playwright-прогоне браузер записал одно `ERR_SSL_PROTOCOL_ERROR` загрузки ресурса; источник не установлен (на страницах ошибок нет, все запросы приложения 200).
