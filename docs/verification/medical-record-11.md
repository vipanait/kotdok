## Миграции

- **С нуля.** `supabase db reset` → весь интеграционный набор зелёный.
- **Обновление старой базы.** База откатана до `20260923200000` (до медкарты) и заполнена по-старому:
  - питомец с весом в анкете, «привит» и двумя лекарствами;
  - питомец без данных;
  - мягко удалённый питомец;
  - питомец владельца, чей аккаунт в статусе удаления.

  Затем `supabase migration up`. **Найдена и исправлена ошибка:** перенос «привит» в миграции `20260925120000_pet_health_events.sql` падал на аккаунте в статусе удаления (защита от поздней записи), и вся миграция откатывалась. Теперь переносятся только активные аккаунты. После исправления:
  - «привит» перенесён в ответ владельца;
  - лекарства из анкеты стали курсами без даты начала;
  - удалённый питомец и аккаунт в удалении не тронуты;
  - повтор миграции ничего не удваивает (MR-06.1).
- **Отключение без удаления данных.** Разделы медкарты перечисляет `writable` в обзоре, справочник закрыт флагом. Приложение без этих экранов продолжает читать анкету: терпимые схемы чтения, неизвестные виды записей пропускаются.
- **Побочный эффект в локальной среде.** После `db reset` у Supabase CLI 2.115 схема storage новее, чем запущенный ранее контейнер storage-api 1.73.1. Фото-тесты падали, пока не выполнены `supabase stop` и `supabase start`. К коду это не относится.

## Не проверено — нужен владелец

1. **Физические устройства:**
   - iPhone: напоминания (разрешение, отказ, отключение в ОС), PDF и «Поделиться» в Telegram и Gmail;
   - Android: всё то же. Особенно PDF без JavaScript (поля и подвал в полях страницы) и то, что файл не исчезает до чтения получателем.
2. **360×640, VoiceOver/TalkBack, 200% шрифт.** На 200% в симуляторе межстрочные интервалы на всех экранах, включая старые, растянуты в несколько раз. Причина в общем `Text` (commit `bcc6fd9`, line height масштабируется дважды), дефект старше медкарты. Предложен отдельной задачей. 360×640, VoiceOver и TalkBack не проверялись.
3. **Справочник вакцин и средств** не проверен ветеринаром. В проде он пуст, пока продукты не будут проверены и помечены `verified`.
4. **Качество ответов модели с медкартой** (MR-10) на реальном OpenAI — прогон сценариев на стейджинге.
5. **Решения владельца, накопившиеся по этапам:**
   - закрывать ли старый план при записи сделанной прививки через «+» (MR-05);
   - просить ли дату окончания у курса из давнего визита (MR-07);
   - повторять ли шторку напоминаний после отказа в системе (MR-08);
   - как склонять женские имена на согласную (MR-08);
   - считать ли вчерашний диагноз «прошлым» (MR-10).
6. **Выпуск:**
   - владелец выполняет `db push` миграций в Supabase (никогда не `supabase config push`);
   - затем слияние в `main` (это деплой);
   - EAS-сборка: добавлены нативные модули `expo-notifications`, `expo-print`, `expo-sharing` — нужна новая сборка, OTA-обновления недостаточно.

## Итоговое ревью всей ветки

Независимое ревью `8765341..06c2f70` — проблемы на стыках этапов. Критичных нет. Исправлено, каждое — тестом, который сначала падал (`medical-record-forms.test.ts`, тесты контрактов):

1. **Важное.** Сохранение анкеты перезаписывало ответ владельца «привит» вычисленным значением. После удаления ошибочной прививки питомец оставался «привит». Теперь значение, отправленное без изменений, ответ владельца не меняет (закрывает и старые клиенты).
2. **Важное.** Анкета, открытая раньше, завершала курсы, добавленные с тех пор, и записывала старый вес как сегодняшний. Теперь приложение отправляет, с чем форма была открыта (`medications_before`, `weight_kg_before`). Завершается только то, что владелец убрал; вес пишется, только если его изменили. Клиент без этих полей ведёт себя по-старому. Проверено в симуляторе: сохранение анкеты не тронуло вес, лекарства и ответ о прививке.
3. **Важное.** У внешних ключей медкарты не было индексов, которые может использовать каскад, и удаление аккаунта сканировало таблицы всех пользователей. Добавлена миграция `20260925210000_medical_record_fk_indexes.sql`; план запроса — Index Scan.
4. Мелкое: старое приложение не читало обзор с новым видом визита, новой единицей интервала или новым полем веса. Теперь такой визит пропускается, интервал сбрасывается, лишние поля отбрасываются (тест).
5. Мелкое: PDF, оставленный для получателя на Android, удаляется при выходе из аккаунта.

Отложено по итоговому ревью:
- «Текущий курс» для анкеты и обзора включает ещё не начавшийся; сводка и проверка — нет.
- В хэш идемпотентности `create_health_event` и `create_visit` не входит питомец. Повтор ключа для другого питомца отвечает 404, данные не портит.
- Нет ограничения частоты на записи медкарты; чтение обрезается на 500 записях.
- **Окно между `db push` и деплоем.** Старый сервер пишет «привит» и лекарства прямо в колонки. После деплоя стоит перезапустить перенос:
  - `select public.backfill_pet_medications();`;
  - перенос `vaccinated_form` для активных аккаунтов.
