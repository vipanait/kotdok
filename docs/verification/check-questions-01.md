## Что сделано

Владелец может задать по одной проверке до трёх вопросов в течение 48 часов и получить короткий ответ модели с учётом описания, результата и медкарты. Кредиты не тратятся. Запись проверки, история и случай наблюдения для установленных сборок не изменились.

## Решения и отклонения

Все отклонения от плана записаны с причиной; ни одно не меняет поведение, описанное в спеке.

1. Ключ, использованный для другого вопроса, — 409 `conflict` с `details.reason = idempotency_key_reused`, как на остальных адресах: отдельного кода ошибки в контракте нет.
2. `position` — номер свободного места (1–3), а не порядок в переписке; переписка читается по `created_at`. Иначе вопрос, место которого освободилось после сбоя, ломал бы нумерацию.
3. Списки признаков опасности вынесены из промпта анализа в `triage-signs.ts`, чтобы оба промпта читали один список. Тест сверяет текст промпта анализа дословно.
4. Выдержки из базы знаний стоят в системном сообщении, как у анализа.
5. Проверке без вида питомца достаются оба списка признаков (кошки и собаки).
6. Тесты сервиса — интеграционные, на локальной базе с подменённой моделью, по образцу `followup-03`, а не модульные с поддельным Supabase.
7. Порядок в сервисе: лимит частоты → чтение проверки → резервирование места. Язык ответа берётся из проверки до резервирования.
8. Вопросы не по теме не попадают в контекст повторной проверки.
9. У клиента API появился срок ожидания на один вызов; общий срок остался 30 с.
10. `askCheckQuestion` передаёт `?today=`, как `POST /checks`, — медкарта читается на день владельца.
11. `questionsForRecheck` вынесен в отдельный модуль, иначе цикл импортов.
12. После слияния main (#109, источники) `getVetContext` возвращает и нумерованные материалы. Ответ на вопрос берёт текст и вычищает пометки вида `[1]`, как анализ.
13. По итогам ревью поиск по базе знаний для вопроса ограничен 5 с без повтора. При сбое ответ строится без выдержек, а не падает: стоящий эндпоинт эмбеддингов с умолчаниями клиента (минута, две попытки) выводил функцию за 90 с.
14. Вопрос не по теме сохраняет плашку, если модель её подняла («наш второй кот съел яд»). Спека говорила `alert = none`; правило «тревожный признак не теряется» важнее. Спека исправлена.
15. Проверка без питомца ищет по базе знаний как кошачья, как и её анализ; списки опасных признаков в промпт идут оба.

## Непроверенное и риски

- Миграция не применена в прод. Её применяет владелец (`supabase db push`) перед слиянием или вместе с ним.
- Стоимость вызовов не измерялась. Верхняя граница — 3 вызова на проверку плюс лимит 20 в час на пользователя.
- Ручной прогон — десять вопросов на одной проверке. Это проверка промпта, а не гарантия поведения модели.
