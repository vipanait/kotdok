## Найдено и исправлено

**Приложение: вторая повторная проверка открывалась без случая.** После отправленной повторной проверки «Проверить снова с учётом прошлой» вело на форму с первым питомцем списка (Мурка вместо Рекса) и без плашки «Учтём проверку…». Причина: вкладка проверки остаётся смонтированной; переход передавал питомца и случай параметрами, их эффект выбирал питомца, а затем на входе во вкладку `startFresh()` очищал отправленную форму вместе с выбором. Исправление: запрос повторной проверки передаётся через `features/followup/recheck-request.ts` (как `pending-check`) и читается во вкладке на входе — после очистки. Проверено в симуляторе на том же сценарии (отправленная повторная проверка → новая отметка → «Проверить снова»): Рекс и «Учтём проверку от 25 октября и 8 отметок»; юнит-тест в `followup.test.ts`.

## Непроверенное и замечания

- Уведомления в этом прогоне не ждались: доставка и текст проверены в симуляторе при реализации (отчёт приложения, M-06), расписание всех оставшихся вопросов — юнит-тестами.
- Android, физический iPhone, VoiceOver — не проверялись.
- Медкарта на сайте в панели браузера первые ~35 секунд показывает скелетон: запросы к API уходят только после этого. Задержка до первого запроса, не в API (ответы 100–270 мс); в фиче цикла наблюдения не появилась, причина не установлена.
- Нажатие в симуляторе не переключает нативный `Switch`, перетаскивание переключает — особенность ввода симулятора, не приложения.
- Первое нажатие на переключатель сайта во время первой записи предложения игнорируется (переключатель занят, «Сохраняем…») — так задумано; в dev-сборке первая запись идёт несколько секунд из-за компиляции маршрута.
