# Форма отчёта об этапе

Это форма, а не свидетельство выполненных работ. При создании отчёта заполнить все разделы; неприменимость объяснить. Скопировать все ID приёмки соответствующего этапа из дорожной карты.

## Паспорт

| Поле | Значение для заполнения |
| --- | --- |
| Этап и название | Номер и название из дорожной карты |
| Статус | IN_PROGRESS / BLOCKED / FAILED / ACCEPTED |
| Даты работы | Начало и окончание либо дата промежуточного отчёта, с часовым поясом |
| Версия плана | Ревизия или сохранённая версия требований |
| Проверенный код | Commit SHA; при dirty tree — базовый SHA и точный перечень/артефакт изменений |
| PR / коммиты | Проверенные ссылки либо «не создан» |
| Окружение | Локальное / staging, версии runtime и инструментов, без секретов |
| Сборки | Build ID, платформа, ОС и модель устройства либо обоснованная неприменимость |

## Что сделано

Объяснить получившееся поведение и отличие от состояния до этапа.

| Файл или компонент | Что изменено | Зачем | ID пункта плана |
| --- | --- | --- | --- |

## Решения и отклонения

Перечислить архитектурные решения, изменения объёма и их причины. Для изменённых требований указать основание и влияние на следующие этапы. Если отклонений нет — так и записать.

## Матрица приёмки

Каждый ID этапа — отдельная строка. Несколько условий одного ID должны быть проверены все; частичный успех не даёт PASS.

| ID | Критерий из плана | Способ проверки | Ожидаемый результат | Фактический результат | PASS / FAIL / NOT RUN | Ссылка на запись проверки |
| --- | --- | --- | --- | --- | --- | --- |

## Автоматические проверки

| Набор / назначение | Точная команда и рабочий каталог | Ревизия | Exit code | Passed / failed / skipped | Лог или запись запуска |
| --- | --- | --- | --- | --- | --- |

Объяснить, где используются моки, где настоящая БД/сервисы и какие гарантии тесты не проверяют. Если числа или coverage не измерялись, написать «не измерено», не 0.

## Ручные проверки

Для каждого сценария записать: ID, предусловия и тестовые данные, последовательность действий, ожидаемое поведение, фактический результат, статус, исполнитель, устройство/ОС/build ID, ссылка на свидетельство. При невозможности выполнить — причина и действие, необходимое для проверки.

## Ошибки и повторные проверки

| Дефект / исходный сбой | Воспроизведение и первая запись | Причина / исправление | Повторная запись и результат | Остаточные ограничения |
| --- | --- | --- | --- | --- |

Сохранять ссылки на неуспешные запуски. Не перезаписывать их последним успешным результатом.

## Непроверенное и риски

Перечислить NOT RUN/FAIL, причины, блокируют ли они приёмку, кто/что требуется для завершения. Указать ограничения тестов, недоступные аккаунты, устройства и внешние проверки. Не смешивать «код написан» и «работает на устройстве».

## Итог и следующий шаг

Указать количество критериев PASS/FAIL/NOT RUN, итоговый статус и его обоснование. ACCEPTED требует PASS всех обязательных критериев этапа и заполненного отчёта. Сослаться на следующий этап или конкретное действие для снятия блокировки.

## История проверок

Список ссылок на все записи в `runs/stage-<номер>/` в порядке времени. Каждая запись содержит дату, ревизию, окружение, выполненные команды/действия, ожидаемый и фактический результат и артефакты. Новые проверки добавляются отдельными файлами; исправления старых записей оформляются явной поправкой без удаления первоначального результата.
