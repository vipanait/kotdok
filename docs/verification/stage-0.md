## Найденные дефекты

1. **Обратная связь не работала в production** — маршрут `/api/feedback` обращался к таблице `public.user_feedback` и колонке `profiles.feedback_submitted_at`, которых в рабочей базе не было. **Исправлено:** по решению владельца миграция применена; отпечатки схем рабочей базы и локального стенда совпали полностью.
2. **История миграций рабочей базы не соответствовала репозиторию** — **исправлено.** `supabase_migrations.schema_migrations` был пуст, поэтому `supabase db push` попытался бы применить весь набор заново, включая незащищённый `alter table public.cats rename to pets`. По решению владельца история выровнена: по одной записи на каждый файл миграции, одинаково на локальном стенде и в рабочей базе. Утверждение «эти версии применены» подтверждено совпадением отпечатков схем, а не принято на веру. Подробности — в записи [20260906-083630Z](runs/stage-2/20260906-083630Z.md).
3. **Боевые ключи доступны preview-деплоям Vercel** — `SUPABASE_SERVICE_ROLE_KEY` и `OPENAI_API_KEY` заданы для Production, Preview и Development одновременно и помечены Non-sensitive. Любая ветка, отправленная в репозиторий, собирается и запускается с боевым service-role-ключом. **Не исправлено:** изменение настроек проекта хостинга — решение владельца.
4. **Одинаковые version-префиксы миграций** — исправлено переименованием; до этого CLI не мог применить набор целиком.
5. **Отсутствовал нативный бинарник Next SWC** — исправлено переустановкой пакета.

Базовые предупреждения Supabase security advisors и 14 уязвимостей `npm audit` зафиксированы в записи цикла проверки как исходное состояние и не исправлялись: план требует отдельного изменения безопасности до публикации.
