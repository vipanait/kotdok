## Решения и отклонения

- FB-1/01 расширен на экраны запланированной записи: в симуляторе оказалось, что у визита на завтра главная кнопка там тоже «Был».
- FB-1/02 расширен на отметку позиции плана: текст «План станет сделанной записью» всплыл при проверке.
- FB-1/03: подписи «Уже был» / «Запланировать» вместо «Визит уже был» / «Запланировать визит» из первой редакции критерия — длинные не помещаются в переключатель; критерий в плане поправлен.
- FB-1/04: ответы на уточнения свёрнуты в одну строку («Аппетит: ест меньше · Активность: …»): списком они сдвигали срочность за первый экран.
- Контракт не менялся: списки и раньше были массивами, поменялась только форма.

## Ручные проверки

Симулятор iPhone 17e, локальный стек. Тестовый пользователь `fb1@fixture.local` создан через admin API локального Supabase, вход — по magic link (`lapka://auth/callback?token_hash=…`), без пароля. Данные засеяны SQL: кошка «Мурка» со списками, визит «Осмотр» на 20 октября, прививка «Нобивак Tricat» на 10 октября (просрочена), одна проверка «Наблюдаем».

## Ошибки и повторные проверки

- Metro сначала не запустился: в корневом `node_modules/expo-modules-autolinking` не было папки `build/`. Пакет переустановлен (`npm install`, lockfile не изменился).
- Во время горячей перезагрузки один раз появился `ReferenceError: marksFromRow` — между правкой экрана и правкой импорта. После полной перезагрузки ошибки нет.

## Ревью

Не проводилось.

## Непроверенное и риски

- Android не проверялся.
- FB-1/05 с несколькими питомцами не проверен вручную.
- Английские тексты проверены только тестами i18n на полноту ключей.
- В «Важно знать» и в сводке для врача списки по-прежнему склеиваются через запятую, поэтому пункт «рыба, кроме лосося» читается как два. Не входит в FB-1, стоит поправить отдельно.
- Сайт не менялся: на вебе списки остаются через запятую.

## Итог и следующий шаг

Все семь пунктов сделаны, шесть приняты в симуляторе, один частично. Дальше: ревью, PR, слияние (EAS Update после него), затем этап FB-2.
