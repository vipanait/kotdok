## Исправленные исходные ошибки

1. **Сборка.** `node_modules/@next/swc-darwin-arm64` содержал только `package.json` и `README.md`; нативный `next-swc.darwin-arm64.node` (116 МБ) отсутствовал. Переустановка пакета (`rm -rf` + `npm install --no-save`) вернула бинарник, после чего `npm run build` завершается с кодом 0. Конфигурация bundler не менялась.
2. **TypeScript TS2554** в `tests/api/billing/billing-routes.test.ts`: обработчик `GET` маршрута `/api/billing/transactions/[id]` объявлен без параметров, а тест вызывал его с двумя. Вызов приведён к фактической сигнатуре, неиспользуемый помощник `params` удалён. Поведение маршрута не менялось.
3. **TypeScript TS2345** в `tests/server/security/csrf.test.ts`: стандартный `RequestInit` допускает `signal: null`, а конструктор `NextRequest` — нет. Тип помощника заменён на `NonNullable<ConstructorParameters<typeof NextRequest>[1]>`.
4. **Lint.** Служебный каталог `supabase/.temp`, создаваемый CLI, попадал в область ESLint и давал 182 ошибки на сгенерированных файлах. Добавлен в `globalIgnores`.

## Восстановление схемы (0/02)

`supabase start` на пустой базе падал на первой же миграции: `relation "public.cats" does not exist`. В репозитории отсутствовали определения создания исходных таблиц.

Схема восстановлена в `supabase/migrations/20260101000000_init_baseline.sql` как состояние **непосредственно перед** `20260422_soft_delete_cats.sql`. Источник — структура рабочей базы (только метаданные каталога, пользовательские данные не читались) за вычетом всего, что добавляют существующие миграции.

Второе препятствие: у нескольких миграций совпадал version-префикс (`20260423`, `20260502` ×4, `20260506`, `20260804`), из-за чего CLI падал на `duplicate key ... schema_migrations_pkey`. Файлы переименованы в уникальные 14-значные версии с сохранением прежнего порядка применения. Переименование безопасно: `list_migrations` рабочего проекта возвращает пустой список — миграции туда применялись вручную, истории CLI нет.

После этого `supabase db reset` применяет все 14 миграций на пустой базе без ручного SQL, exit 0.

### Сверка с рабочей базой

Построен отпечаток схемы (колонки, ограничения, индексы, политики, состояние RLS, функции, триггеры, enum), сгруппированный по объектам и захешированный. Совпали **все** объекты, кроме:
