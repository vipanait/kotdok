# Этап 4 — первая сборка на устройстве 20260906-124143Z

База: коммит `29e8898`, ветка `main`. Симулятор iPhone 17 Pro, iOS 26.5, Xcode 26.6.

Владелец установил Xcode, чем снял пункт 1.13 для iOS. Android SDK отложен его решением — Apple проверяем первым.

## Инструментарий

`xcode-select` указывает на `/Applications/Xcode.app`, `xcodebuild` версии 26.6, доступны SDK `iphoneos26.5` и `iphonesimulator26.5`, восемь симуляторов. CocoaPods отсутствовал; системный Ruby 2.6 для него слишком стар, поэтому поставлен через Homebrew — версия 1.17.0 со своим Ruby. Это единственное, что добавлено на машину.

## Что подтвердилось

Нативная сборка проходит: `expo prebuild` создаёт `ios/` (каталог в `.gitignore`, приёмка 0.1/08 не нарушена), поды встают, `xcodebuild` собирает, приложение запускается и открывает экран входа. До установки Xcode это было невозможно в принципе.

Приложение смотрит в тестовый проект — подтверждено логами Supabase: запросы приходят с `User-Agent: Lapka/1 CFNetwork/3860.600.12 Darwin/25.6.0` на `rclnsbivyulqmvujiopv`.

## Дефект, который нашла именно сборка на устройстве

**Войти было нельзя.** Сессия Supabase против тестового проекта — 2291 байт: 990 токена доступа и 1158 объекта пользователя. `SECURE_STORE_VALUE_LIMIT` равен 2048, запись отвергалась, и приложение осознанно выходило с сообщением «Не удалось сохранить вход на этом устройстве». Каждый вход, всегда.

Ни один из 23 тогдашних тестов этого не ловил: они проверяли поведение вокруг лимита, но настоящую сессию с ним никто не сравнивал.

Исправлено разбиением значения на куски (`29e8898`). Тестов стало 30; четыре новых падают на прежней реализации.

**Проверка на устройстве после правки:** вход доходит до экрана «Питомцы» без сообщения об ошибке записи, и сессия переживает холодный перезапуск — приложение открывается сразу на «Питомцах». В логе Supabase соответствующий `200`.

## Чего проверка не покрыла

**Продуктовые экраны.** `EXPO_PUBLIC_API_URL` равен `http://localhost:3000`, там ничего не запущено, поэтому `api.listPets()` даёт «Нет связи с сервером». Обойти нечем: локальный `next dev` подтянет `.env.local` с боевыми ключами и получится приложение в staging против production, а развёрнутый preview закрыт аутентификацией Vercel, заголовок обхода приложение не шлёт.

**Ввод через `simctl` оказался ненадёжен.** Из четырёх попыток входа, которые вёл агент, одна ушла с пустым полем почты, в другой поле показывало `mbilecheck` вместо `mobilecheck` — потерян символ. Логи Supabase показывают `400` на все четыре и `200` на те же данные через `curl` двадцатью секундами позже. Ручной ввод владельца проходил с первого раза. Вывод для пункта 3.4: инструмент мобильных E2E придётся выбирать с оглядкой на надёжность ввода, синтетические нажатия по координатам сами по себе не годятся.

**Нативная сборка под устройство и подпись** — не проверялись, только симулятор.
