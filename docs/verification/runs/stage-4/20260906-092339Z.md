## Что проверено автоматически

### Хранилище сессии

| Случай | Поведение |
| --- | --- |
| Обычная запись и чтение | значение сохраняется и читается |
| Хранилище не читается | считается «сессии нет», приложение не падает при запуске |
| Запись не удалась | вызывается обработчик, значение не сохранено, приложение **не** считает себя вошедшим |
| Значение длиннее 2048 байт | отклоняется до обращения к хранилищу — предел Android SecureStore |
| Значение ровно 2048 байт | принимается |
| Выход | все записанные ключи удалены, чтение возвращает `null` |
| Ошибка удаления при выходе | выход всё равно завершается |

Смысл: сессия, которую не удалось записать, хуже отсутствующей — она исчезает при следующем запуске без объяснения. Поэтому неудачная запись приводит к управляемому выходу, а не к молчаливому продолжению.

### Обновление токена

| Случай | Поведение |
| --- | --- |
| Три параллельных запроса получили `401` | обновление выполнено **один** раз, все три получили один и тот же новый токен |
| Следующее истечение токена | обновление выполняется снова |
| Обновление вернуло отказ | выход выполняется один раз на все ожидающие запросы |
| Обновление бросило исключение | трактуется как потерянная сессия, а не как падение |

Смысл: экран, который грузит питомцев, профиль и историю сразу, получит три `401` подряд. Обновление на каждый запрос израсходовало бы refresh-токен трижды, а при ротации второй и третий уже недействительны — пользователя выкинуло бы без причины.

Адрес возврата строится приложением, а не берётся из входных данных, поэтому подменить его через параметр нельзя.

## Проверка бандла — исправление прошлой ошибки

Раньше я проверял мобильные бандлы на секреты через `grep -rl`. Это давало ложную уверенность: бандлы — байткод Hermes, и `grep` не находит в них строки, которые там заведомо есть. Проверено: `grep` не видит `rclnsbivyulqmvujiopv`, а `strings` находит его в том же файле.

Заменено на `scripts/check-bundle.mjs`, который читает печатные строки и **декодирует** каждый найденный JWT, то есть судит по тому, чем токен является, а не на что похож. Проверено, что скрипт срабатывает: на подложенный `service_role`-токен он отвечает `carries a JWT with role "service_role"` и завершается с кодом 1.

Фактическое содержимое бандлов: ровно один JWT, роль `anon`, ref `rclnsbivyulqmvujiopv` — публичный клиентский ключ **тестового** проекта. Ни `service_role`, ни ключей OpenAI, Resend и Telegram, ни ref production в бандлах нет. Проверка подключена к CI.
