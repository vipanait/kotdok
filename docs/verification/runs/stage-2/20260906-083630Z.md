## Выравнивание истории

До этого цикла `supabase_migrations.schema_migrations` содержала только записи, созданные Management API при ручных применениях: `20260906071541 feedback`, `20260906075750 account_status_and_write_lockdown`, а затем `20260906083337 rate_limits` и `20260906083349 deleting_accounts_lose_access`. Ни одна из версий репозитория отмечена не была, поэтому `supabase db push` попытался бы применить весь набор заново — включая `alter table public.cats rename to pets` без защиты `IF EXISTS`.

Записи заменены на одну строку на каждый файл миграции. Management API при этом добавил собственную строку для самой операции выравнивания — `20260906083441 align_migration_history`; в репозиторий добавлен одноимённый файл, который локально является no-op, чтобы обе истории описывали один и тот же набор.

**Результат:** и локальный стенд после `supabase db reset`, и рабочая база содержат одни и те же 18 версий в одном порядке.

Утверждение «эти версии действительно применены» не принято на веру: оно подтверждено сравнением схем, см. ниже.

## Сверка после применения

Отпечаток схемы расширен правами на выполнение функций — раньше он их не покрывал, и именно там нашлась разница между `revoke ... from anon, authenticated` и `revoke ... from public, anon, authenticated`.

| Сторона | Отпечаток | Объектов |
| --- | --- | --- |
| Локальный стенд после `supabase db reset` | `5fe093e880c757afea4837f8115df45f` | 101 |
| Рабочая база | `5fe093e880c757afea4837f8115df45f` | 101 |

Состояние рабочей базы: 25 аккаунтов, все `active`; `api_rate_limits` пуста — счётчики появятся, когда новый код будет выкачен.

## Смоук production

`https://lapka.my` — `/`, `/login`, `/pricing` отвечают 200 и рендерят приложение. Политики чтения изменены, но все аккаунты активны, поэтому для текущих пользователей поведение прежнее.

## Что это меняет для выката

Раньше ветку нельзя было выкатывать: код обращается к `api_rate_limits` и `consume_rate_limit`, которых в рабочей базе не было. Теперь схема готова, и это ограничение снято.

Отдельно: код ветки в production не развёрнут. `lapka.my` продолжает отдавать сборку из `main`.
