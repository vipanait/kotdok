Статус: **IN_PROGRESS**. Пять пунктов из шести приняты; 2/02 частично — продуктовых маршрутов v1 ещё нет. Этап не закрыт.

Исполнимый план: [stage-2-api-auth.md](../superpowers/plans/stage-2-api-auth.md).

## Что сделано

- `/api/v1` принимает только Bearer-токен; cookies в этом пути не читаются, отката к сессии браузера нет.
- Единый конверт ответа: `request_id`, коды ошибок контракта, `Cache-Control: private, no-store`.
- Реализованы `/api/v1/health` и `/api/v1/me`; ответ `/me` парсится контрактом перед отправкой.
- Распределённые ограничения частоты на общей БД: два экземпляра сервера расходуют одну квоту.
- Аккаунт в состоянии `deleting` теряет доступ **на всех путях**, включая прямое чтение через PostgREST со старым JWT.

## Найденное при реализации

**`revoke execute` без `public` не закрывает функцию.** PostgreSQL по умолчанию выдаёт `EXECUTE` роли `PUBLIC`, поэтому отзыв только у `anon` и `authenticated` оставил бы новую функцию лимитера доступной через `/rest/v1/rpc`. Поймано тестом до выката. Существующие billing-функции этим не затронуты — проверено на рабочей базе; миграции billing уже используют правильную форму. Заодно закрыт `handle_new_user`, который помечает Supabase-линтер.

**Чтение при `deleting` не было закрыто.** Политики спрашивали только владельца строки, поэтому пользователь с начавшимся удалением продолжал читать свои данные до истечения JWT. Исправлено миграцией.
