## Что сделано

### Раздел «Паразиты» (макеты `parasites`, `parasites-empty`)

`/pets/[id]/health/parasites` — статическая папка рядом с `[recordId]`, как у прививок.

- **Списки.** Сначала планы по возрастанию, затем сделанное по убыванию. Карточка называет препарат и группы: «Бравекто Спот-он · блохи, клещи».
- **Две карточки сбоку: «Блохи и клещи» и «Глисты».** В каждой:
  - последняя обработка и её препарат;
  - ближайший план: словами и значком, если он просрочен или близко; иначе «Следующая — 5 октября»;
  - ссылка «Сделано» на эту позицию.
- **Где считается.** Какая обработка последняя и какой план ближайший, решает общий `parasiteCovers` в `packages/shared` (`record-overview.ts`). Мобильный `parasiteStatuses` теперь берёт его же, собственной копии нет. Комбинированный препарат учитывается в обеих карточках.
- **Пустой раздел:** «Обработок пока нет» и «Добавить обработку». В карточках групп — «Обработок не записано» и «Следующая не запланирована».
- **Форма обработки** — форма событий MW-03 с `kind="parasite"`. Справочник только противопаразитарных средств для вида питомца; чипы — «Блохи», «Клещи», «Глисты» (`toggleParasiteGroup`). У каждой позиции своя следующая дата по интервалу её препарата. «Обработка от паразитов» появилась в «Что добавить?».

### «Сделано» — одна позиция плана

Адрес: `/pets/[id]/health/[recordId]/complete[?item=…][&from=due|medical|section]`. Это подмаршрут записи. В списке маршрутов handoff его нет, это дополнение.

**Как выбирается позиция:**
- `item` указан — отмечается она;
- у плана одна позиция — сразу форма;
- у плана их несколько — вопрос «Какая прививка/обработка сделана?» (макет `planned-complete`) с кнопкой на каждую позицию. Остальные позиции остаются в плане.

**Когда формы нет:**
- выполненная запись — сервер перенаправляет на её просмотр;
- чужой, удалённый или несуществующий план — 404;
- позиция, которой уже нет в плане, — «Эту позицию уже не отметить».

**Форма** (макеты `planned-rabies-complete`, `parasite-complete`):
- плашка «Сделано» и «Было запланировано на …»;
- «Когда сделали» — по умолчанию сегодняшний день владельца (`localToday`, часовой пояс браузера), не позже сегодняшнего;
- позиция показана только для чтения: препарат и «От чего / От кого»;
- следующая дата предлагается от фактической даты по интервалу позиции в его собственной единице. Подсказка называет интервал («Предложено по интервалу препарата: 12 недель»). Дату можно изменить или очистить. Без интервала дата не подставляется, как в MW-03;
- клиника и заметка берутся из плана — сервер всё равно сохраняет клинику плана;
- сводка: «Отметим только эту позицию: ещё 1 позиция останется в плане. Следующий срок — 17 декабря.» либо «План станет выполненной записью. …»;
- предупреждение, как в MW-03: «После сохранения выполненную запись нельзя будет изменить. Проверьте дату и препараты.».

**Логика вне React** (`complete-form.ts`): `completionTarget`, `completeDraft`, `changeDoneDay` и `readCompletion`. Последняя проверяет поля через общие правила дат `eventDayProblem` и `nextDayProblem`, затем через `CompleteItemInputSchema` контракта.

**Сохранение:**
- один `Idempotency-Key` на форму (`useSaveKey`): повтор после обрыва отправляет тот же ключ;
- на время отправки кнопка получает `aria-disabled`, повторные нажатия не уходят;
- любая ошибка оставляет форму открытой со всеми полями, говорит причину у кнопок, и кнопка снова работает;
- 409 `conflict` — «уже сохранена раньше», 404 — «позиции плана больше нет».

**После успеха:**
- из «Все сроки» и из раздела — возврат туда с «Отмечено сделанным.»;
- из плана и из медкарты — просмотр выполненной записи.

**Расчёт интервала — только в `packages/shared`:**
- `addInterval`: недели считаются днями, месяцы — календарными месяцами;
- для месяцев `addInterval` теперь вызывает `addMonths` — одно правило вместо двух копий внутри shared;
- мобильное приложение пользуется тем же `addInterval` и `suggestNextDay`.

### «Сделано» для плана прививки и обработки

- В просмотре плана появились «Сделано» и «Изменить». Для плана из нескольких позиций «Сделано» ведёт к выбору позиции.
- Серверный путь один для обоих видов: `complete_health_item` и `plan_next_items` берут `kind` события. Проверено интеграционным тестом и в браузере на прививке «Нобивак Rabies» из плана с двумя вакцинами: вторая осталась в плане.
- Отложенное замечание MW-03 закрыто: просмотр записи учитывает `overview.writable`. Если сервер не хранит этот вид записей, нет ни «Изменить», ни «Сделано», ни удаления.

### Сроки: медкарта и «Все сроки» (макет `due`)

- **Медкарта.** Первые три срока, у каждой позиции прививки или обработки кнопка «Сделано». Ссылка «Все сроки · N» есть всегда, когда включён этап сроков.
- **`/pets/[id]/health/due`.** Все сроки питомца: заголовок «Все сроки · 5», ссылка «Медкарта», строка на каждую позицию со своей «Сделано».
- **Порядок: просроченные, ближайшие, остальные.** Данные — события обзора с сервера, порядок — общий `dueEntries`.
  - Серверный `/api/v1/pets/due` сортирует так же. Внутри одного дня добавлен порядок «новые первыми, затем id», как в обзоре; раньше у одинаковых дат порядка не было.
  - Интеграционный тест сравнивает оба списка.
- **Состояние срока** сказано словами и значком (календарь, календарь с отметкой). Цвет только поддерживает:
  - просроченное — нейтральный тёмный текст, жирный;
  - ближайшее — зелёное;
  - дальнее — приглушённое, без значка, как в макете.

  Красных бейджей срочности нет: `urgencyBadgesInDue: 0`.
- **Кнопка «Сделано»** — таблетка высотой 44 px. Доступное имя: «Сделано: Блохи и клещи, просрочено на 14 дней · 12 сентября».
- **Визиты** стоят в сроках без «Сделано»: «Был» появится в MW-06.

### Сервер и мобильное приложение

- Контракты не менялись, миграций нет.
- Изменение сервера одно: порядок внутри дня в `listDue`. Мобильное приложение читает этот список для напоминаний (`ReminderProvider`) и для строки срока в списке питомцев (первая дата). Меняется только порядок позиций одного дня: какая из них показана первой.
- Мобильное приложение изменилось только в `parasiteStatuses`: логика ушла в shared. Мобильные тесты зелёные (41 файл, 351 тест).

## Дефекты, отклонения, непроверенное

1. **Отклонения от макета:**
   - в «Сделано» позиция не редактируется: в макете `parasite-complete` есть чипы и «Добавить препарат», но контракт `CompleteItemInput` принимает только дату, следующую дату, клинику и заметку. Форма повторяет `planned-rabies-complete`: позиция только для чтения;
   - раздел называется «Паразиты», как в макете и на карточке медкарты (было «Обработки от паразитов»);
   - адрес `…/[recordId]/complete` — новый подмаршрут, в списке маршрутов handoff его нет;
   - у дальних сроков нет значка, только приглушённая дата, как в макете `due`.
2. **Повтор с тем же ключом, но другими данными, у плана из одной позиции.** Такой план сам становится выполненной записью и хранит собственный ключ, поэтому сервер возвращает уже выполненную запись (200) с прежней датой, а не 409. Форма покажет успех, запись — с первой датой. Дублей нет. У плана из нескольких позиций ответ — 409, форма говорит «уже сохранена раньше». Поведение `complete_health_item` не менялось.
3. **Гонка «Сделано» и правки плана** (из MW-03) не закрыта — нужна миграция.
4. **Своё название без интервала:** на вебе следующая дата не подставляется, на телефоне берётся запасной интервал (`fallbackInterval`). Правило MW-03 сохранено.
5. **Визиты в сроках — без «Сделано»** до MW-06.
