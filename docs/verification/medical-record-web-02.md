## Что сделано

**Маршруты** (`implementation-handoff.md`, «Маршруты»):

| Адрес | Что это |
|---|---|
| `/pets/[id]/health/weight` | Раздел «Вес». Статическая папка рядом с `[recordId]`, поэтому раздел и запись различаются на уровне маршрутизации. Следующие этапы добавят `vaccinations`, `parasites` и т.д. так же. |
| `/pets/[id]/health/new` | «Что добавить?» (макет `add`): только открытые этапом типы, сейчас «Вес». |
| `/pets/[id]/health/new?type=weight` | Новое измерение. Неизвестный тип или тип закрытого этапа — 404. |
| `/pets/[id]/health/[recordId]` | Запись. `recordId` — только UUID живой записи этого питомца и этого владельца, иначе 404. У измерения веса нет отдельного просмотра (история показывает все значения), поэтому адрес ведёт на форму. |
| `/pets/[id]/health/[recordId]/edit` | Изменение записи. Сейчас — измерение веса. |

Серверная часть страниц:
- `components/cabinet/open-pet-page.ts` — общий вход всех страниц медкарты, в том числе `/pets/[id]`: вход, владелец, живой питомец. Чужой, удалённый и неверный id — 404.
- `server/medical-record/record-lookup.ts` — `findHealthRecord`: запись ищется по `id`, `pet_id`, `user_id`, `deleted_at is null`. Следующие этапы добавят свои виды записей.

**Раздел «Вес»** (макеты `weight`, `weight-one`):
- «Полгода / Год / Всё» — `aria-pressed`, по умолчанию полгода.
- Период фильтрует точки графика, тренд и подпись графика. Используются общие `weightsInPeriod` и `weightTrend(…, period)`; параметр периода добавлен в `packages/shared`, по умолчанию год — шапка медкарты и мобильное приложение не изменились.
- Две точки и больше — график (общие `chartLayout`/`chartTicks`), подпись для экранного диктора «График веса за полгода: от 4,4 до 4,2 кг» и скрытый список точек.
- Меньше двух точек — вместо графика фраза:
  - одно измерение за всё время или только вес анкеты — «Добавьте ещё одно измерение, чтобы увидеть изменения.» (как в макете);
  - одна точка в периоде при большем числе в истории — «Одно измерение за полгода — …»;
  - период без измерений — «Измерений за полгода нет. Последнее — 10 января 2025.».
- Веса нет совсем — «Измерений пока нет».
- Таблица «Измерения» — все измерения, новые сверху: дата с годом, «из анкеты» для значений анкеты, вес, ссылка. У ссылки `aria-label` называет измерение. Даты и значения читаются без графика.
- «Уточнить»:
  - у старого веса анкеты без истории (Бобик) — открывает новое измерение, как в макете;
  - у недатированной строки истории — её форму с пустой датой.
- Справа — «Одна история веса». На ≤900 px она стоит первой, как в макете 390.

**Форма** (макеты `weight-new`, `weight-edit`):
- Поля читает общий модуль `packages/shared/src/medical-record/weight-entry.ts`. Мобильная шторка теперь использует его же — её копия `parseWeight`/`weightPatch` удалена.
  - Границы — из контракта: значение проверяется самой схемой `WeightInputSchema.shape.weight_kg` (больше 0, не больше `WEIGHT_MAX_KG` = 200).
  - Поле добавляет только правило §7.13 «один знак после запятой», отсюда минимум 0,1.
  - «4,2» и «4.2» → `4.2`. Строка читается как десятичный литерал, поэтому в запросе ровно `"weight_kg":4.2`.
  - Будущая дата запрещена по дню владельца (`localToday`), у поля даты `max` = сегодня.
- Новое измерение: вес пустой, дата — сегодня. Изменение: поля заполнены этим измерением. У недатированного измерения дата пустая и может остаться пустой: исправляется только вес, дата не выдумывается.
- Изменение отправляет только то, что изменилось. Если не изменилось ничего, запроса нет.
- Сохранение:
  - во время запроса кнопка «Сохраняем…», `aria-busy`, поля только для чтения, повторное нажатие ничего не отправляет;
  - при ошибке поля сохраняются, баннер объясняет причину, кнопка снова работает;
  - 409 (день занят) показывается у поля даты;
  - после успеха — возврат в историю с сообщением «Вес сохранён.» (фокус на нём, из адреса оно убирается);
  - кэш медкарты этой вкладки сбрасывается, а `router.refresh()` перечитывает серверные страницы. Раздел, шапка медкарты и анкета показывают новое значение: анкету сервер держит на последнем измерении.
- Ключ идемпотентности: у endpoint веса его нет в контракте, и он не нужен. `POST` записывает измерение за день (второе сохранение того же дня заменяет значение), `PATCH` задаёт значения. Повтор того же сохранения оставляет ту же историю — это проверено тестом (два одинаковых `POST` → одна строка). Удаление измерения, которого уже нет (404 на повторе), форма считает выполненным.
- Удаление:
  - вопрос называет измерение: «Удалить измерение 4,6 кг, 26 сентября 2026?»;
  - начальный фокус на «Не удалять»;
  - Escape и отмена возвращают фокус на «Удалить измерение»;
  - ошибка удаления показывается в диалоге.
- Уход из изменённой формы по любой ссылке страницы — диалог «Уйти без сохранения?». Перезагрузка и закрытие вкладки — вопрос браузера. Логика вынесена в `features/forms/use-leave-guard.ts`, анкета питомца переведена на тот же хук без изменения поведения (проверено: диалог, «Остаться», «Уйти»).

**Медкарта**: флаг `MEDICAL_RECORD_STAGE.weight = true`. На `/pets/[id]` появились «Все →» у карточки «Вес» и «Добавить запись» (ведёт в «Что добавить?»). График карточки и график раздела — один компонент `WeightChart.tsx`.

## Дефекты и непроверенное

1. **`schema.test.ts`, 2 падения** — известный шум окружения из MW-01: в общей локальной базе есть `personal_data_consents` и `pd_consent_version_is_current` из миграции другой ветки. К MW-02 не относится.
2. **HTTP-статус чужой страницы — 200** (`foreignPages[].status`). Интерфейс — 404, данные не утекают, но `pets/loading.tsx` начинает поток раньше `notFound()`. Та же отложенная оговорка MW-01, проверяется в MW-08.
3. **`consoleErrors` в выводе вызваны самим прогоном**: `ERR_INTERNET_DISCONNECTED` — намеренный обрыв сохранения, `409` — проверка переноса на занятый день.
4. **Кнопка «Назад» браузера** в изменённой форме не спрашивает (перехватываются ссылки страницы, перезагрузка и закрытие вкладки). Так же ведёт себя анкета.
5. **Вес анкеты с двумя знаками** (например, 4,25, внесённые через анкету) открывается в форме измерения, но сохранить его без исправления до одного знака нельзя. Это правило §7.13, то же в мобильной шторке.
6. **«Уточнить» у веса анкеты без истории** добавляет датированное измерение. Сервер при этом сохраняет прежнее значение анкеты недатированной строкой (модель `record_pet_weight`), поэтому в таблице появляются обе строки. Это поведение сервера, не новое.
7. **Не проверено:** экранный диктор вживую, масштаб 200 %, экранная клавиатура iOS и Safari (iOS Simulator не запускался на этом этапе), мобильное приложение в симуляторе (изменён только источник `parseWeight`/`weightPatch`, юнит-тесты мобильного проходят).
