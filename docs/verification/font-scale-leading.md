# Межстрочный интервал при крупном системном шрифте

## Паспорт

| Поле | Значение |
| --- | --- |
| Что | Исправление: `lineHeight` масштабировался дважды при крупном системном шрифте |
| Даты работы | 20 октября 2026, Europe/Moscow |
| Проверенный код | ветка `mobile/font-scale-leading` поверх `de089be` |
| Окружение | Локально: Supabase CLI 2.115 (`supabase start`), `next dev -p 3100` с `.env.integration`, Expo Metro 8081 с локальным `.env.local` |
| Сборки | Отладочная сборка iOS из DerivedData в симуляторе iPhone 17e (iOS 26.5); бандл JS из этой ветки. React Native 0.86.3. Нативных изменений нет |

## Симптом

На `xcrun simctl ui booted content_size accessibility-large` межстрочный интервал рос
намного сильнее глифов на всех экранах: «Кот · Сибирская · 4 года» переносилось с
пустой строкой между строк, строки в «Сроках» стояли в коробках по ~65 pt.

## Причина

`apps/mobile/src/ui/Text.tsx` умножал `lineHeight` из темы на `PixelRatio.getFontScale()`,
считая, что React Native его не масштабирует. React Native 0.86 масштабирует сам, тем же
множителем и с тем же потолком `maxFontSizeMultiplier`, что и `fontSize`:

- iOS: `RCTAttributedTextUtils.mm`, `lineHeight * RCTEffectiveFontSizeMultiplierFromTextAttributes(...)`;
- Android: `TextAttributes.effectiveLineHeight`, `PixelUtil.toPixelFromSP(lineHeight, effectiveMaxFontSizeMultiplier)`.

Итог — множитель в квадрате. Замер по пикселям на `accessibility-large` (множитель 2.143),
строка вида питомца — вариант `caption`, 12/16:

| | Высота глифов (кегль + нижний вынос) | Шаг строк | Ожидание |
| --- | --- | --- | --- |
| До | 24.7 pt | ≈ 73 pt | 16 × 2.143² = 73.5 pt |
| После | 24.7 pt | ≈ 34 pt | 16 × 2.143 = 34.3 pt |

Глифы не изменились, изменился только интервал.

Ручное умножение появилось в `bcc6fd9` (8 сентября) после того, как отчёт
`runs/stage-7/20260908-131000Z.md` сначала нашёл правильный ответ («React Native 0.86
масштабирует межстрочное сам»), а потом откатил его из-за обрезанных глифов. Версия
React Native с тех пор та же — 0.86.3, и на этой сборке обрезания без ручного множителя
нет (кадры 05–08). Что именно обрезалось в сентябре, отсюда не восстановить.

## Исправление

`Text.tsx` передаёт стиль варианта из темы как есть. Значения типографики и темы не менялись.
`CONTROL_FONT_LIMIT` (потолок 1.5× для подписей кнопок и заголовка экрана) работает как
раньше: React Native применяет `maxFontSizeMultiplier` и к размеру, и к интервалу.

| Что | Размер | Результат | Кадр |
| --- | --- | --- | --- |
| Карточка питомца в списке | accessibility-large | До: разрыв в строку между «4» и «года». После: обычный перенос | 01 → 02 |
| «Сроки» на экране питомца | accessibility-large | До: каждая строка в коробке ~65 pt. После: интервал по дизайну | 03 → 04 |
| Карточка питомца, кнопка, таб-бар | accessibility-extra-extra-extra-large | Выносы «у», «р» целы; кнопка и подписи табов не обрезаны | 05 |

`tsc --noEmit` в `apps/mobile` чистый. Модульных тестов на компонент нет: тесты мобильного
приложения — чистая логика без рендера React Native.

## Не проверено

| Что | Почему |
| --- | --- |
| Android | В SDK нет эмулятора и образов системы, устройство по adb не подключено. По исходникам React Native Android масштабирует `lineHeight` так же (`TextAttributes.effectiveLineHeight`), так что двойной множитель был и там, и правка его убирает |
| Экраны входа, профиля, форм медкарты | Проверены экраны из постановки: карточка питомца, «Сроки», результат проверки, кнопки, таб-бар. Правка общая для всего `Text`, поэтому отдельные экраны не дают нового сигнала |
