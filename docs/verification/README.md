# История выполнения и проверок

Источник требований: [дорожная карта](../mobile-api-plan.md). Формат подробного отчёта: [REPORT_TEMPLATE.md](REPORT_TEMPLATE.md). Всё нерешённое и непроверенное собрано в [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md).

Этапы 0 и 0.1 в работе: исходные проверки выполнены, локальный стенд и фикстуры готовы, репозиторий переведён на workspaces с отдельным Expo-приложением. Часть пунктов заблокирована внешними решениями. PLANNED означает отсутствие принятого результата, а не успешную проверку. Ниже этапы расположены в согласованном порядке исполнения.

| --- | --- | --- | --- |

Открытые блокеры и вопросы к владельцу перечислены в [OPEN_QUESTIONS.md](OPEN_QUESTIONS.md): нет отдельного тестового проекта Supabase, preview-деплои Vercel работают с боевыми ключами, не проверены лимиты выполнения и runtime worker, ни один ручной сценарий сайта не пройден.

После каждого этапа обновить статус и добавить ссылку на `stage-<номер>.md`. При незавершённой работе сохранить промежуточный отчёт. Записи циклов проверки хранятся отдельно в `runs/stage-<номер>/<YYYYMMDD-HHMMSSZ>.md`, включая неудачные запуски.
