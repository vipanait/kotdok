# История выполнения и проверок

Источник требований: [дорожная карта](../mobile-api-plan.md). Формат подробного отчёта: [REPORT_TEMPLATE.md](REPORT_TEMPLATE.md).

Этапы 0 и 0.1 в работе: исходные проверки выполнены, локальный стенд и фикстуры готовы, репозиторий переведён на workspaces с отдельным Expo-приложением. Часть пунктов заблокирована внешними решениями. PLANNED означает отсутствие принятого результата, а не успешную проверку. Ниже этапы расположены в согласованном порядке исполнения.

Открытые блокеры и вопросы к владельцу: preview-деплои Vercel и Supabase используют боевые ключи, отдельного тестового проекта нет (0/04); история миграций рабочей базы не соответствует репозиторию и правка отклонена политикой разрешений; не проверены лимиты выполнения, резервное копирование и runtime worker (0/06); маршрутизация CI не наблюдалась на GitHub, так как workflow не срабатывает на push в ветку (0.1/05); preview закрыт защитой Vercel, поэтому HTTP smoke после переноса не выполнен (0.1/06); ручные сценарии сайта не пройдены. Подробности — в [отчёте этапа 0](stage-0.md) и [docs/architecture/deployment.md](../architecture/deployment.md).

После каждого этапа обновить статус и добавить ссылку на `stage-<номер>.md`. При незавершённой работе сохранить промежуточный отчёт. Записи циклов проверки хранятся отдельно в `runs/stage-<номер>/<YYYYMMDD-HHMMSSZ>.md`, включая неудачные запуски.
