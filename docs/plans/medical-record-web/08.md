## Сделать

Подключить listDue к обзору: одна строка ближайшего просроченного/ближайшего в пределах 14 дней срока у питомца. Не создавать N+1 запрос на медкарту каждого питомца. Сохранить компактный обзор при пяти и более питомцах, существующие проверки и лимиты.

Проверить подсказки в анкете и согласованность legacy полей с медкартой. Текущий API уже учитывает медицинский контекст; не создавать новый независимый prompt. Пройти межплатформенный сценарий веб→mobile→веб.

Провести регрессию, адаптивность, клавиатуру, screen reader, долгие запросы, повтор, отсутствие сети, два аккаунта. Прототипные заглушки не переносить в приложение. Подготовить итоговый отчёт и перечень реальных ограничений; включать этапы по готовности, не выдавать mock за реализованную функцию.

## Приёмка

1. У пяти питомцев обзор остаётся компактным, «Все питомцы» открывает полный список; срок ведёт к нужному питомцу.
2. Созданная в вебе запись видна в mobile; изменение в mobile появляется после обновления веба.
3. На 320/390/768/1024/1440 px нет горизонтального скролла; sticky-действия не закрывают последние поля и нижнюю навигацию.
4. Проверены Chrome desktop, Safari desktop и Safari iOS; ошибки сохранения сохраняют введённые данные.
5. Пройдены проверки авторизации, изоляции владельцев, idempotency и регрессия существующих функций. Нет запроса browser push или новых email-напоминаний.

## Как закрыть этап

Продемонстрировать сценарии приёмки на реальном API с тестовым владельцем и отдельным чужим владельцем для проверки доступа. Для изменённой логики добавить полезные интеграционные/компонентные проверки; не тестировать совпадение CSS с самим собой. Выполнить доступные typecheck/lint и релевантные тесты текущего workspace, указав точные команды и результат.

Создать `docs/verification/medical-record-web-08.md`: commit/окружение, критерий → доказательство, скриншоты 390 и 1440, выполненные тесты, дефекты/непроверенные пункты. Не закрывать критерий без проверки. Не переключаться к следующему этапу при незакрытом обязательном критерии; описать блокер и его минимальное исправление. Не менять опубликованные данные и не деплоить без отдельного запроса.
