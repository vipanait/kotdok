## Сделать

Подключить getCatalog(species, kind, query), createHealthEvent/changeHealthEvent/deleteHealthEvent. Реализовать Сделано/Запланировано, несколько позиций, название из справочника, своё название и запись без препарата с целями. Веб-справочник — combobox в форме; на телефоне список не выходит за края.

Популярные 6–8 результатов при фокусе, поиск по названию/производителю, пустой результат, ошибка и ручной ввод. Обязательность полей и даты — по контракту. Интервал справочника только предлагает следующую дату, владелец может изменить/убрать её.

Показывать основные прививки отдельно для вида. Не выдавать legacy «привит» за прививку с подтверждённой датой. Продуктовые примеры в макете не являются проверенным справочником для production.

## Приёмка

1. Сохранить две вакцины одним событием, открыть только для просмотра, проверить после перезагрузки. Изменять можно запланированную запись; удаление ошибочной записи требует подтверждения.
2. Собаке не предлагаются кошачьи препараты; переключение питомца отменяет устаревший поиск.
3. Ручной ввод работает при недоступном каталоге. Пустые цели у записи без препарата блокируют сохранение.
4. Повтор отправки с одним idempotency key не создаёт дубль. После ошибки поля сохранены.
5. Клавиатура: стрелки, Enter, Escape, aria-expanded, подписи результата; отмена удаления сохраняет запись.

## Как закрыть этап

Продемонстрировать сценарии приёмки на реальном API с тестовым владельцем и отдельным чужим владельцем для проверки доступа. Для изменённой логики добавить полезные интеграционные/компонентные проверки; не тестировать совпадение CSS с самим собой. Выполнить доступные typecheck/lint и релевантные тесты текущего workspace, указав точные команды и результат.

Создать `docs/verification/medical-record-web-03.md`: commit/окружение, критерий → доказательство, скриншоты 390 и 1440, выполненные тесты, дефекты/непроверенные пункты. Не закрывать критерий без проверки. Не переключаться к следующему этапу при незакрытом обязательном критерии; описать блокер и его минимальное исправление. Не менять опубликованные данные и не деплоить без отдельного запроса.

### Приоритетное уточнение: выполненное неизменяемо

Правило владельца от 26 сентября: сделанные прививки и обработки нельзя редактировать. Проверить отсутствие действия в UI, защиту прямого edit-URL и отказ PATCH выполненного события на сервере. Запланированная запись редактируется с сохранением её ID, даты и позиций. После выполнения становится только для просмотра. Перед изменением общего endpoint проверить и согласовать поведение мобильного клиента. API пока допускает правки; это часть работ, не готовое свойство системы. Отмена редактирования возвращает к исходному плану. Взвешивание/анкета не являются выполненной процедурой.
