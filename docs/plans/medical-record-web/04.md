## Сделать

Переиспользовать форму событий и справочник с kind обработки. Разделять блохи/клещи/глисты, у каждой позиции собственная следующая дата.

Подключить completeHealthItem: «Сделано» выполняет конкретную позицию, а не всё многопозиционное событие. Фактическая дата предлагается сегодня; пересчёт следующего срока учитывает единицу интервала, например 12 недель — не 3 месяца. План и отмена не создают выполненную обработку.

Список сроков берёт серверные данные и порядок: просроченные, ближайшие, остальные; главная показывает первые три и переход ко всем. Текст и значок поддерживают цвет. Не смешивать просроченность с медицинской срочностью проверки.

4. Повтор завершения безопасен, ошибки не закрывают форму и не показывают ложный успех.

## Как закрыть этап

Продемонстрировать сценарии приёмки на реальном API с тестовым владельцем и отдельным чужим владельцем для проверки доступа. Для изменённой логики добавить полезные интеграционные/компонентные проверки; не тестировать совпадение CSS с самим собой. Выполнить доступные typecheck/lint и релевантные тесты текущего workspace, указав точные команды и результат.

Создать `docs/verification/medical-record-web-04.md`: commit/окружение, критерий → доказательство, скриншоты 390 и 1440, выполненные тесты, дефекты/непроверенные пункты. Не закрывать критерий без проверки. Не переключаться к следующему этапу при незакрытом обязательном критерии; описать блокер и его минимальное исправление. Не менять опубликованные данные и не деплоить без отдельного запроса.

### Приоритетное уточнение: выполненное неизменяемо

Правило владельца от 26 сентября: сделанные прививки и обработки нельзя редактировать. Проверить отсутствие действия в UI, защиту прямого edit-URL и отказ PATCH выполненного события на сервере. Запланированная запись редактируется с сохранением её ID, даты и позиций. После выполнения становится только для просмотра. Перед изменением общего endpoint проверить и согласовать поведение мобильного клиента. API пока допускает правки; это часть работ, не готовое свойство системы. Отмена редактирования возвращает к исходному плану. Взвешивание/анкета не являются выполненной процедурой.
