## Сделать

Подключить createVisit/changeVisit и существующее удаление события. Реализовать причину, клинику, врача, диагноз, заметки и несколько назначений. «Принимает сейчас» у назначения использует prescriptionToMedication; не дублировать курс при повторном действии.

Добавить «Записать визит к врачу» в результат проверки; передать assessment id и исходный контекст через реальные идентификаторы. Показать связанную проверку в визите и обратную навигацию. Из карточки результата не переносить демонстрационную дату 2 августа: для новой формы использовать правила актуальной даты из спецификации.

Разделить запланированный и состоявшийся визит. Назначения не превращать автоматически в активные лекарства без выбора владельца.

## Приёмка

1. Создать визит из результата и напрямую; только первый имеет корректную связь с проверкой.
2. Два назначения сохраняются после перезагрузки; выбранное появляется в курсах ровно один раз.
3. Повтор создания/выполнения визита не размножает назначения/лекарства; состоявшийся визит нельзя редактировать.
4. Запланированный визит можно отметить состоявшимся, отменить или перенести; сроки обновились.

## Как закрыть этап

Продемонстрировать сценарии приёмки на реальном API с тестовым владельцем и отдельным чужим владельцем для проверки доступа. Для изменённой логики добавить полезные интеграционные/компонентные проверки; не тестировать совпадение CSS с самим собой. Выполнить доступные typecheck/lint и релевантные тесты текущего workspace, указав точные команды и результат.

Создать `docs/verification/medical-record-web-06.md`: commit/окружение, критерий → доказательство, скриншоты 390 и 1440, выполненные тесты, дефекты/непроверенные пункты. Не закрывать критерий без проверки. Не переключаться к следующему этапу при незакрытом обязательном критерии; описать блокер и его минимальное исправление. Не менять опубликованные данные и не деплоить без отдельного запроса.
