# Веб-медкарта «Лапки»: план реализации

Дата: 26 сентября 2026. Статус: передача в разработку. Этот пакет — дизайн и план, не готовая веб-фича.

## Что передать следующему агенту

Передайте этот README. Все необходимые документы связаны ниже и находятся в репозитории.

> Реализуй веб-медкарту по docs/plans/medical-record-web/README.md. Начни с MW-01, переиспользуй существующие API/контракты медкарты. Выполняй по одному этапу с его приёмкой и отчётом. Сверяй экран с docs/design/medical-record-web-v1/. Не создавай повторную модель данных и не переносись к следующему этапу с непроверенными обязательными критериями. Сохраняй существующие изменения других агентов.

## Обязательное уточнение владельца · 26 сентября

Выполненные процедуры и состоявшиеся визиты недоступны для редактирования; изменяются только планы. Для лекарств редактируется текущий курс, завершённый — просмотр. Вес/анкета не являются выполненными процедурами. Это заменяет прежние пункты о редактировании сделанных записей. Новый запрет требуется обеспечить на сервере с проверкой влияния на mobile; существующий API ещё не менялся. [Аудит форм](../../design/medical-record-web-v1/form-audit.md).

## Что уже существует

В репозитории есть `packages/contracts/src/medical-record.ts`, `health-targets.ts`, portable helpers в `packages/shared/src/medical-record/`, методы в `packages/shared/src/api-client.ts`, серверные сервисы `apps/web/src/server/medical-record/` и маршруты `apps/web/src/app/(backend)/api/v1/pets/[id]/health/`. Каталог находится в `api/v1/health/catalog`, общий список сроков — `api/v1/pets/due`.

Мобильная реализация: `apps/mobile/src/features/medical-record/`. Отчёты: `docs/verification/medical-record-01.md`…`medical-record-11.md`. Это основание для повторного использования, а не доказательство наличия миграций/данных в конкретном окружении. На MW-01 проверить доступность нужных endpoint в целевом окружении и актуальность схем. Новые миграции нужны только при доказанном пробеле.

## Общие правила

- Не переносить static JS макета в production. Веб: Next.js, React, существующие компоненты и авторизация. Перед кодом читать актуальные руководства `node_modules/next/dist/docs/` согласно AGENTS.md.
- Общие packages остаются portable: без DOM, Next.js, native и серверных SDK.
- Все операции ограничены владельцем; проверять доступ на сервере, а не только скрывать ссылки.
- Повтор одного сохранения использует тот же idempotency key, новая логическая операция — новый. Не отключать кнопку навсегда после ошибки.
- Даты хранятся/передаются согласно contracts; не превращать календарную дату в случайный предыдущий день через UTC. «Сегодня» зависит от согласованного часового пояса.
- Изменения инвалидируют связанные чтения: overview, раздел, список сроков, summary и анкету при необходимости. Не держать раздельные источники лекарств/веса.
- Справочник production показывает только разрешённые проверенные записи. Локальный флаг для unverified продуктов не включать на production.
- Веб не запрашивает разрешение на уведомления, не создаёт service worker push, email-напоминания или native-настройки.
- После MW-08 итоговый отчёт `docs/verification/medical-record-web-final.md` со ссылками на все этапы и оставшимися ограничениями. Деплой отдельно от реализации.
