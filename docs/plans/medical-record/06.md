# MR-06. Лекарства и синхронизация анкеты

> Для исполняющего агента: прочитать [общий план](README.md), исходную спецификацию и выполнить только этот этап через `superpowers:executing-plans`. Следующий этап не начинается автоматически.

**Цель:** Владелец ведёт текущие и завершённые курсы, а анкета показывает тот же список.

**Зависит от:** 01; после 05 по выбранному порядку.

**Макеты:** М18, М19, X-course, X-legacy-course, X-meds-empty.

**Архитектура:** вертикальный этап: контракт → сервер/хранение → мобильный UI → проверки. Новые серверные маршруты входят в `/api/v1`; UI использует общий API-клиент.

**Стек:** текущие Expo/React Native, Next.js API, PostgreSQL, Zod, Vitest. Версии и инструкции проверяются в репозитории перед кодом.

## Файлы и границы

- `supabase/migrations/<новая_метка>_pet_medications.sql (новый)`
- `apps/web/src/server/medical-record/medication-service.ts (новый)`
- `apps/web/src/server/pets/pet-service.ts`
- `apps/mobile/src/features/medical-record/MedicationsScreen.tsx (новый)`

Новые пути — предлагаемая структура. Если эквивалент уже появился, расширить его и зафиксировать фактический путь, не создавать дубль. Для миграции `<новая_метка>` заменить на следующую свободную метку времени репозитория.

## Шаги

- [ ] Зафиксировать базовые проверки и убедиться, что зависимости этапа приняты, а не просто начаты.
- [ ] Создать тестовые сценарии по MR-06.1…4 ниже; для логики данных сначала воспроизвести отсутствие/ошибку поведения на минимальном тесте.
- [ ] Создать pet_medications и контракты курса: название, как давать, начало, окончание/постоянно, происхождение, связи с назначением.
- [ ] Старые пункты анкеты переносить идемпотентно как текущие курсы без подробностей. Не выдумывать историческое начало. Новые пункты анкеты получают сегодняшнюю дату по спецификации.
- [ ] Серверно синхронизировать активные курсы и pets.medications; новые пункты создают курс, удалённые завершают сегодня и сохраняются в истории. Повторная синхронизация не создаёт дублей.
- [ ] Создать формы нескольких курсов, группы Сейчас/Раньше, просмотр, изменение и завершение курса.
- [ ] Для лекарства использовать свободный ввод и подсказки пользователя; никаких интервалов вакцинации и ежедневных напоминаний. Проверять окончание не раньше начала.
- [ ] Запустить адресные тесты, проверки типов и регрессию затронутых старых сценариев. Проверки SQL-транзакций/RLS выполнить на изолированной тестовой базе, не ограничиваться моками.
- [ ] Сверить UI с указанными артбордами; записать доказательства для каждого критерия в `docs/verification/medical-record-06.md`. Отдельно записать то, что проверить не удалось.
- [ ] Представить рабочий результат этапа на приёмку. Незакрытые критерии означают, что этап не завершён.

## Нумерованные критерии приёмки

- [ ] **MR-06.1** Повтор миграции/синхронизации старых данных не удваивает курсы.
- [ ] **MR-06.2** Завершение в медкарте убирает пункт анкеты, удаление в анкете завершает курс без удаления истории.
- [ ] **MR-06.3** Два назначения с одним названием, но разными датами/дозировками не объединяются по строке названия.
- [ ] **MR-06.4** Без подробностей / постоянно / конечная дата / неверный диапазон отображаются и валидируются отдельно.
