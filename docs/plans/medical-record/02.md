# MR-02. Вес: первая законченная функция

> Для исполняющего агента: прочитать [общий план](README.md), исходную спецификацию и выполнить только этот этап через `superpowers:executing-plans`. Следующий этап не начинается автоматически.

**Цель:** Можно добавлять, исправлять и удалять измерения; анкета и график показывают одни данные.

**Зависит от:** 01.

**Макеты:** М10, М20, X-weight-one.

**Архитектура:** вертикальный этап: контракт → сервер/хранение → мобильный UI → проверки. Новые серверные маршруты входят в `/api/v1`; UI использует общий API-клиент.

**Стек:** текущие Expo/React Native, Next.js API, PostgreSQL, Zod, Vitest. Версии и инструкции проверяются в репозитории перед кодом.

## Шаги

- [ ] Зафиксировать базовые проверки и убедиться, что зависимости этапа приняты, а не просто начаты.
- [ ] Создать тестовые сценарии по MR-02.1…4 ниже; для логики данных сначала воспроизвести отсутствие/ошибку поведения на минимальном тесте.
- [ ] Создать миграцию pet_weights с владельцем, pet_id, датой измерения, значением и мягким удалением; гарантировать одно действующее измерение на питомца и дату. Добавить правила доступа и карту удаления.
- [ ] Ввести контракты измерений и GET/POST/PATCH/DELETE /pets/{id}/health/weights. В серверной транзакции синхронизировать последний по дате вес с анкетой.
- [ ] Для старого веса без даты хранить происхождение «из анкеты» и неизвестную дату; не объявлять дату миграции медицинской датой измерения. После первого датированного измерения использовать его для актуального веса.
- [ ] Добавить шторку веса: диапазон 0,1–200, одна десятичная цифра, запятая/точка, дата; повторное измерение в тот же день обновляет запись.
- [ ] Реализовать график и периоды Полгода/Год/Всё, текстовый список и нейтральный тренд. При одной точке показывать объяснение. Удаление последнего измерения возвращает согласованное nullable-значение, не ноль.
- [ ] При изменении веса через существующую анкету записывать/обновлять сегодняшнее измерение; при удалении последнего по дате пересчитывать предыдущий.
- [ ] Запустить адресные тесты, проверки типов и регрессию затронутых старых сценариев. Проверки SQL-транзакций/RLS выполнить на изолированной тестовой базе, не ограничиваться моками.
- [ ] Сверить UI с указанными артбордами; записать доказательства для каждого критерия в `docs/verification/medical-record-02.md`. Отдельно записать то, что проверить не удалось.
- [ ] Представить рабочий результат этапа на приёмку. Незакрытые критерии означают, что этап не завершён.

## Нумерованные критерии приёмки

- [ ] **MR-02.1** 4,2 и 4.2 сохраняют одинаковое значение; 0, отрицательное, >200 и нечисловое значение отклоняются.
- [ ] **MR-02.2** Добавление старой даты не меняет текущий вес; изменение/удаление последней даты пересчитывает его.
- [ ] **MR-02.3** Два одновременных сохранения на одну дату не создают дубликаты.
- [ ] **MR-02.4** Нет точек / одна точка / три точки / один вес во всех точках: график без деления на ноль, список доступен диктору.
