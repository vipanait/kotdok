# MR-09. Сводка для врача и PDF

> Для исполняющего агента: прочитать [общий план](README.md), исходную спецификацию и выполнить только этот этап через `superpowers:executing-plans`. Следующий этап не начинается автоматически.

**Цель:** Все сведения можно показать врачу и отправить PDF через системную панель.

**Зависит от:** 02–07.

**Макеты:** М11, М28, X-pdf-loading, X-pdf-error.

**Архитектура:** вертикальный этап: контракт → сервер/хранение → мобильный UI → проверки. Новые серверные маршруты входят в `/api/v1`; UI использует общий API-клиент.

**Стек:** текущие Expo/React Native, Next.js API, PostgreSQL, Zod, Vitest. Версии и инструкции проверяются в репозитории перед кодом.

## Нумерованные критерии приёмки

- [ ] **MR-09.1** PDF для Мурки содержит все разделы; Бобик не получает данные Мурки и фиктивное отсутствие болезней.
- [ ] **MR-09.2** Кириллица, длинный диагноз, <script> в заметке, необычные символы имени не ломают HTML и имя файла.
- [ ] **MR-09.3** Много визитов/препаратов: таблицы и подвал не обрезаются, чёрно-белая печать сохраняет смысл.
- [ ] **MR-09.4** Системный обмен и его отмена проверены на обеих платформах; ошибка подготовки допускает повтор.
