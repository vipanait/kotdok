# MR-08. Локальные напоминания

> Для исполняющего агента: прочитать [общий план](README.md), исходную спецификацию и выполнить только этот этап через `superpowers:executing-plans`. Следующий этап не начинается автоматически.

**Цель:** Телефон напоминает о реальных планах; управление доступно в профиле.

**Зависит от:** 03, 05, 07.

**Макеты:** М12, М23–М25, X-profile, X-system.

**Архитектура:** вертикальный этап: контракт → сервер/хранение → мобильный UI → проверки. Новые серверные маршруты входят в `/api/v1`; UI использует общий API-клиент.

**Стек:** текущие Expo/React Native, Next.js API, PostgreSQL, Zod, Vitest. Версии и инструкции проверяются в репозитории перед кодом.

## Шаги

- [ ] Зафиксировать базовые проверки и убедиться, что зависимости этапа приняты, а не просто начаты.
- [ ] Создать тестовые сценарии по MR-08.1…5 ниже; для логики данных сначала воспроизвести отсутствие/ошибку поведения на минимальном тесте.
- [ ] Добавить совместимую с текущим Expo версию expo-notifications и проверить native configuration в development build. Не рассчитывать на Expo Go.
- [ ] Реализовать чистую функцию плана уведомлений: pet_id, item_id, date, вид, настройки, текущее время. Группировать по питомцу и дню, убирать прошлые уведомления, упорядочивать ближайшие, соблюдать лимит iOS 64.
- [ ] Запрашивать разрешение после первого сохранённого плана; «Не сейчас» на 30 дней, отказ ОС ведёт в настройки. Сроки остаются видимыми независимо от разрешения.
- [ ] Добавить локальные настройки этого устройства: on/off, 1/3/7 дней, 08–21, по умолчанию 3 дня и 10:00. Пересчитать расписание при открытии приложения, изменении записи и настроек.
- [ ] При переносе, отмене, завершении, удалении питомца, выходе/смене аккаунта отменять старые уведомления. При входе восстанавливать только планы текущего владельца.
- [ ] Обработать тап с холодного старта и после авторизации: открывать нужного питомца; если его удалили — безопасный переход в список. Учесть смену часового пояса и даты без сдвига дня.
- [ ] Запустить адресные тесты, проверки типов и регрессию затронутых старых сценариев. Проверки SQL-транзакций/RLS выполнить на изолированной тестовой базе, не ограничиваться моками.
- [ ] Сверить UI с указанными артбордами; записать доказательства для каждого критерия в `docs/verification/medical-record-08.md`. Отдельно записать то, что проверить не удалось.
- [ ] Представить рабочий результат этапа на приёмку. Незакрытые критерии означают, что этап не завершён.

## Нумерованные критерии приёмки

- [ ] **MR-08.1** Отказ/разрешение/отключение в ОС проверены на физических iOS и Android.
- [ ] **MR-08.2** Два плана одного питомца в день дают одно уведомление; 70 будущих уведомлений сокращены до ближайших 64 на iOS.
- [ ] **MR-08.3** Отмена и смена аккаунта не оставляют чужих уведомлений.
- [ ] **MR-08.4** Тесты полуночи, смены часового пояса и перехода летнего времени не сдвигают календарный срок.
- [ ] **MR-08.5** Холодный старт по уведомлению открывает верного питомца после входа.
