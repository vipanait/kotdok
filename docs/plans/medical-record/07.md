# MR-07. Визиты и назначения врача

> Для исполняющего агента: прочитать [общий план](README.md), исходную спецификацию и выполнить только этот этап через `superpowers:executing-plans`. Следующий этап не начинается автоматически.

**Цель:** Записываются прошлые и будущие визиты, назначения создают курсы, результат проверки связан с визитом.

**Зависит от:** 03, 06.

**Макеты:** М9, М17, М26, X-visit-plan, X-visit-record, X-visits-empty.

**Архитектура:** вертикальный этап: контракт → сервер/хранение → мобильный UI → проверки. Новые серверные маршруты входят в `/api/v1`; UI использует общий API-клиент.

**Стек:** текущие Expo/React Native, Next.js API, PostgreSQL, Zod, Vitest. Версии и инструкции проверяются в репозитории перед кодом.

## Шаги

- [ ] Зафиксировать базовые проверки и убедиться, что зависимости этапа приняты, а не просто начаты.
- [ ] Создать тестовые сценарии по MR-07.1…5 ниже; для логики данных сначала воспроизвести отсутствие/ошибку поведения на минимальном тесте.
- [ ] Расширить событие визитом: вид, причина, диагноз, назначения, необязательный check_id. Проверять принадлежность проверки тому же питомцу и владельцу.
- [ ] Сделать Был/Запланировать; диагноз и назначения только у состоявшегося. Добавить полные варианты Осмотр/Болезнь/Операция/Анализы/Другое.
- [ ] Для каждого назначения переключатель «Добавить в лекарства» по умолчанию включён. Создавать курсы транзакционно со связью appointment_item_id; повторное сохранение не дублирует курсы.
- [ ] Из результата, кроме healthy, предзаполнять сегодня, Болезнь, первую строку описания, check_id. Выбор ранее сделанной проверки — за 30 дней; существующая связь не исчезает после истечения этого окна.
- [ ] Список будущих визитов выше прошлого, срок визита участвует в общей очереди. В просмотре доступно добавление ещё не перенесённого назначения в лекарства.
- [ ] При удалении визита не уничтожать созданные из него курсы молча: сохранить курс, удалить связь и сообщить об этом в подтверждении. При правке назначений не перезаписывать отдельно отредактированный курс без явного действия. Это уточнение поведения сверх спецификации.
- [ ] Запустить адресные тесты, проверки типов и регрессию затронутых старых сценариев. Проверки SQL-транзакций/RLS выполнить на изолированной тестовой базе, не ограничиваться моками.
- [ ] Сверить UI с указанными артбордами; записать доказательства для каждого критерия в `docs/verification/medical-record-07.md`. Отдельно записать то, что проверить не удалось.
- [ ] Представить рабочий результат этапа на приёмку. Незакрытые критерии означают, что этап не завершён.

## Нумерованные критерии приёмки

- [ ] **MR-07.1** Визит с двумя назначениями создаёт два курса один раз; выключенный переключатель не создаёт курс.
- [ ] **MR-07.2** Чужая проверка и проверка другого питомца отвергаются сервером.
- [ ] **MR-07.3** План визита не создаёт лечение; после отметки был разрешены диагноз/назначения.
- [ ] **MR-07.4** Удаление/правка визита не уничтожает независимые изменения курса.
- [ ] **MR-07.5** Кнопка визита есть у четырёх уровней срочности и отсутствует у healthy.
