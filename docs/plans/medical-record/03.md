# MR-03. Прививки и планы — сначала ручной ввод

> Для исполняющего агента: прочитать [общий план](README.md), исходную спецификацию и выполнить только этот этап через `superpowers:executing-plans`. Следующий этап не начинается автоматически.

**Цель:** Владелец записывает несколько вакцин за один визит, планирует следующие даты и отмечает отдельные позиции сделанными. Сроки уже работают без уведомлений.

**Зависит от:** 01; рекомендуется после 02.

**Макеты:** М5, М6, М13, М14, М21, М22, X-targets, X-manual, X-dates, X-record, X-cancel.

**Архитектура:** вертикальный этап: контракт → сервер/хранение → мобильный UI → проверки. Новые серверные маршруты входят в `/api/v1`; UI использует общий API-клиент.

**Стек:** текущие Expo/React Native, Next.js API, PostgreSQL, Zod, Vitest. Версии и инструкции проверяются в репозитории перед кодом.

## Нумерованные критерии приёмки

- [ ] **MR-03.1** Две вакцины → одна сделанная запись + два независимых плана.
- [ ] **MR-03.2** Сделано у одной из двух запланированных позиций оставляет вторую в плане; повтор того же запроса не добавляет событий.
- [ ] **MR-03.3** В сделанной записи нельзя будущую дату; в новом плане нельзя прошлую; существующая просрочка остаётся доступной для переноса/отметки.
- [ ] **MR-03.4** Границы вчера/сегодня/14/15 дней и просрочка >2 месяцев дают правильные слова, без цветов срочности.
- [ ] **MR-03.5** Ошибка транзакции не оставляет частично созданных позиций; другой пользователь не может завершить или перенести план.
