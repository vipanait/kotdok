# Прокси для пользователей из России

Сайт и API работают на Vercel, но часть российских сетей не пропускает HTTPS до адресов Vercel. Перед Vercel стоит машина в Yandex Cloud с nginx: `lapka.my` указывает на неё, она передаёт каждый запрос в Vercel с исходным доменом. Деплой, превью, cron и переменные окружения остаются на Vercel.

Статус на 26 сентября 2026: проверено на тестовой машине, DNS ещё указывает на Vercel.

Файлы: [`infra/ru-proxy/`](../../infra/ru-proxy/) — конфиг nginx и два скрипта для сервера.

## Почему

Измерено 26 сентября 2026 через check-host.net (узлы Москва ×2, Санкт-Петербург) и с тестовой машины в Yandex Cloud.

| Откуда → куда | Результат |
| --- | --- |
| Германия → `lapka.my` | всегда 200 |
| Москва (ru1) → `lapka.my` | около 7 из 10 запросов висят 15–25 с и обрываются |
| Москва (ru2), Петербург → `lapka.my` | почти всегда 200 |
| Москва → `kotdok.vercel.app` | висит на обоих московских узлах |
| Все узлы → Supabase | отвечает |
| Все узлы → адреса Vercel по HTTP (порт 80) | отвечает |
| Yandex Cloud → `lapka.my` через `216.198.79.1`, `64.29.17.1`, `76.76.21.21` | 75 из 75 |
| Yandex Cloud → `kotdok.vercel.app` (`…131`) | 8 из 50, TCP не устанавливается |
| Все узлы → машина в Yandex Cloud | TCP 4–14 мс, включая ru1 |

TCP до Vercel устанавливается, HTTPS зависает — это фильтрация у провайдера, а не сбой сервера. Какие адреса Vercel недоступны, зависит от сети. Cloudflare у домена только DNS и к проблеме отношения не имеет.

## Схема

```
браузер, приложение ──► lapka.my, www.lapka.my ──► машина в Yandex Cloud (nginx)
                                                      │  Host и SNI: исходный домен
                                                      ▼
                                   216.198.79.1 / 64.29.17.1 / резерв 76.76.21.21 (Vercel)
```

- Проксируется только `lapka.my` и `www.lapka.my`. Запрос к другому домену отклоняется, иначе машина стала бы прокси ко всем сайтам на Vercel.
- В Vercel идут адреса для собственных доменов, **не** `*.vercel.app`: из Yandex Cloud до последних соединение не устанавливается.
- Сертификат Vercel проверяется (`proxy_ssl_verify on`).
- Ответы не буферизуются: страницы Next.js приходят потоком.
- `/.well-known/acme-challenge/` отвечает сама машина, если файл её, иначе передаёт в Vercel. Так сертификаты продлевают и машина, и Vercel.

**Мимо прокси:** Supabase (вход, загрузка фото — браузер и приложение ходят туда напрямую) и cron Vercel (вызывается внутри Vercel). Приложение не определяет пользователя по IP, поэтому то, что Vercel видит IP машины, ничего не ломает.

## Машина

Облако `cloud-panait-v`, каталог `default`.

| Параметр | Значение |
| --- | --- |
| Образ | Ubuntu 24.04 LTS |
| Зона | `ru-central1-a` |
| Платформа | Intel Ice Lake, 2 vCPU, гарантированная доля 20%, 1 ГБ RAM |
| Диск | HDD 10 ГБ |
| Прерываемая | **нет** — прерываемую Yandex останавливает в любой момент |
| Публичный IP | **статический** (VPC → IP-адреса → «Сделать статическим»), иначе сменится после перезапуска |
| Пользователь | `lapka`, вход по SSH-ключу владельца |

## Установка

```bash
scp infra/ru-proxy/lapka.conf lapka@<IP>:/tmp/
ssh lapka@<IP> 'bash -s' < infra/ru-proxy/install.sh
```

Скрипт ставит nginx и certbot, кладёт конфиг и временный самоподписанный сертификат. Повторный запуск безопасен: выпущенный сертификат не трогается. Чтобы обновить конфиг, те же две команды.

## Проверка до переключения DNS

С любой машины, подставив IP. `-k` — потому что сертификат пока самоподписанный.

```bash
curl -sk -o /dev/null -w "%{http_code}\n" --resolve lapka.my:443:<IP> https://lapka.my/
curl -sk --resolve lapka.my:443:<IP> https://lapka.my/api/v1/health
curl -sk -o /dev/null -w "%{http_code}\n" --resolve lapka.my:443:<IP> https://lapka.my/api/v1/me
```

Ожидается `200`, `{"status":"ok"}` и `401`.

## Переключение DNS

DNS домена — **Cloudflare** (NS `nick.ns.cloudflare.com`, `sierra.ns.cloudflare.com`). SendPulse здесь только отправляет почту, от него в зоне одна SPF-запись; её и MX (`smtp.google.com`) не трогать.

Cloudflare → `lapka.my` → DNS → Records:

| Запись | Было | Стало |
| --- | --- | --- |
| `lapka.my` (`@`) | A `216.198.79.1` | A `<IP машины>`, **DNS only** (серое облако), TTL Auto |
| `www` | CNAME `093fe1e0afef66e1.vercel-dns-017.com` | A `<IP машины>`, **DNS only**, TTL Auto |

Оранжевое облако (проксирование Cloudflare) не включать: адреса Cloudflare в России тоже ограничивают.

Сразу после смены записей выпустить сертификат:

```bash
ssh lapka@<IP> 'bash -s' < infra/ru-proxy/issue-cert.sh
```

Пока он не выпущен, у тех, кого DNS уже направил на машину, браузер предупреждает о сертификате. Обычно это одна-две минуты.

## После переключения

- Вход на сайте через Google, Яндекс, Apple и по почте.
- Мобильное приложение: вход, список питомцев, проверка симптомов.
- Утром — логи Vercel: `/api/cron/deletion-jobs` (03:00 UTC) и `/api/cron/photo-uploads` (03:30 UTC) отработали.
- В Vercel на странице доменов `lapka.my`, вероятно, будет помечен как настроенный неправильно: DNS больше не указывает на Vercel. Это ожидаемо, домен из проекта не удалять.

## Откат

Вернуть записи из таблицы выше («Было»), обе **DNS only**. Через несколько минут трафик снова идёт напрямую в Vercel. Машину можно не трогать.

## Риски и что проверять

- **Сертификат Vercel.** Прокси проверяет его, поэтому если Vercel не продлит сертификат `lapka.my`, сайт начнёт отдавать `502`. Продление идёт через проброс `/.well-known/acme-challenge/`, но на практике ещё не проверялось. Текущий истекает **1 декабря 2026**, продление ожидается в начале ноября. Проверка с машины:
  ```bash
  echo | openssl s_client -connect 216.198.79.1:443 -servername lapka.my 2>/dev/null | openssl x509 -noout -enddate
  ```
- **Адреса Vercel записаны в конфиге.** Если Vercel их сменит, нужно поправить `upstream` в `lapka.conf`. Актуальные адреса — в настройках домена в Vercel.
- **Одна машина.** Упала машина — сайт недоступен для всех, не только для России. Лечится откатом DNS.
- **TLS расшифровывается в Yandex Cloud.** Провайдер технически имеет доступ к трафику, включая данные о питомцах и токены входа.
- **Supabase не проксируется.** Сейчас доступен из всех проверенных сетей. Если его начнут ограничивать — отдельная задача: смена адреса Supabase разлогинит пользователей и потребует обновления приложения.
