# Медкарта · передача мобильному разработчику

Сначала прочитать [исходную спецификацию](../medical-record-spec.md), затем [решения и расхождения](README.md), затем [карту экранов](screen-map.md). Макеты дополняют требования, но не являются реализацией API и справочника. Текущая задача — только дизайн мобильного приложения; код приложения не менялся.

## 1. Навигация и существующие формы

- [ ] Тап по питомцу и завершение создания питомца открывают медкарту; «Анкета» возвращает прежнюю форму.
- [ ] Сохранить состав, порядок и поведение анкеты. Добавить только условные подсказки к весу, вакцинации и препаратам. М27 раскрывает здоровье для просмотра подсказок; это не указание всегда раскрывать секцию в приложении.
- [ ] В списке показать один самый ранний просроченный/ближайший срок, не заменяя бейдж последней проверки.
- [ ] В медкарте нижний таб «Питомцы»; в формах нет нижнего меню. Возврат после записи в исходный раздел того же pet_id.
- [ ] Поддержать переход из напоминания, ссылку на историю этого питомца, переход из результата в визит и подсказку медкарты в проверке.

## 2. Данные и медкарта

- [ ] Синхронизация анкеты и медкарты строго по §4 исходной спецификации, без двойного ввода и потери старых данных.
- [ ] М2 — данные §13: один пропущенный срок и два ближайших; мартовские планы дают полный счётчик 5.
- [ ] На главной не больше трёх сроков; сначала просроченные, затем будущие по дате. Общий счётчик учитывает позиции, не события.
- [ ] Пустые подблоки «Важно знать» и пустой блок сроков скрывать. В сводке неизвестные данные писать «Не указано владельцем».
- [ ] М3 не искусственно пустой: 28 кг и привит из анкеты. Одно измерение без графика. Подсказка скрывается для конкретного питомца навсегда.
- [ ] Статусы сроков — слова и иконки; запрет на emergency/urgent/monitor цвета вне результатов проверок.

## 3. Справочник и многопозиционные формы

- [ ] Первый выбор вакцины/препарата открывает справочник; фокус поиска не автоматический. Только препараты вида текущего питомца, включая оба вида.
- [ ] Поиск по названию/производителю, регистру/раскладке; популярные, пустые результаты, ошибка загрузки.
- [ ] Ручное название и «Без препарата» доступны всегда. Цели выбираются вручную, интервал не выдумывается.
- [ ] Выбор позиции заполняет название, цели, интервал. Смена препарата обновляет всё, не только видимое название. Возможность поправить цели и дату.
- [ ] Добавление/удаление нескольких позиций, отдельные следующие даты; удаление последней позиции даёт ошибку при сохранении.
- [ ] Сделано: сегодня/прошлое; план: сегодня/будущее, без начального значения. В форме запланированной нет «Следующая».
- [ ] «Своя дата» открывает выбор; «Не напоминать» не создаёт план. Дата считается от даты события; 12 недель не равно трём месяцам.
- [ ] «Сделано» у одной позиции не завершает всё многопозиционное событие. На сохранении отделить только её и создать её следующий план.
- [ ] Подтверждение итоговых записей/сроков перед сохранением показано в М6/М16/X-complete; это предложенное дополнение.
- [ ] Клиника с подсказками, необязательная заметка до 300 символов, состояния «Сохраняем…», ошибки и повтор без потери ввода.

## 4. Визиты, лекарства, вес

- [ ] В визите «Был» показывать диагноз и назначения; «Запланировать» скрывает эти поля. Виды визита брать из полного набора §7.11.
- [ ] Несколько назначений, для каждого «Добавить в лекарства», связь с проверкой только того же питомца за последние 30 дней; вариант не связывать.
- [ ] Из результата предзаполнить сегодня, «Болезнь», причину и check_id. Не подменять это демонстрационной датой 2 августа.
- [ ] Лекарства вводятся свободно с подсказками владельца, не через справочник вакцин. Несколько курсов, окончание или постоянно, завершение сегодня и синхронизация анкеты.
- [ ] Вес 0,1–200, один знак после запятой; при одинаковой дате обновление измерения. Последнее по дате значение в анкете.
- [ ] График без зон нормы, ось от минимума минус 10%, подписи значений и доступный список. Одна точка — объяснение вместо линии. Периоды реально фильтруют данные.

## 5. Напоминания и сводка

- [ ] Разрешение запрашивается после первого плана/следующей даты, не при запуске. «Не сейчас» откладывает предложение на 30 дней; планы остаются.
- [ ] После отказа ОС — переход в системные настройки, недоступный переключатель, понятная ошибка.
- [ ] Время 08–21, интервал 1/3/7 дней + день срока; по умолчанию 10:00 и 3 дня. Настройки локальны устройству.
- [ ] Учитывать группировку уведомлений по питомцу/дню и ограничения очереди из §14. Дизайн не предлагает серверные push.
- [ ] Для врача: все разделы §7.17, максимум три последние проверки, до пяти последних измерений, визиты за год, пустые данные не превращаются в «нет».
- [ ] PDF A4 с таблицами, словами срочности, графиком, датой и подписью владельца на каждой странице. Сохранить читаемость чёрно-белой печати; переносить таблицы и не обрезать длинные записи.
- [ ] Подготовка PDF, ошибка, повтор, системное «Поделиться»; публичную ссылку не создавать.

## 6. Проверки перед сдачей

- [ ] 390×844 и 360×640, увеличенный шрифт 200%, клавиатура, длинные имена и диагнозы. Последний элемент прокручивается выше закреплённых действий.
- [ ] Минимум касания 44×44, доступные имена, выбранное состояние чипов, фокус внутри шторок и возврат фокуса при закрытии.
- [ ] На маленькой высоте действия рядом (предложение), без уменьшения зоны касания. При большом шрифте перенос/прокрутка важнее укладки всех сроков без скролла.
- [ ] Кольцо: Бобик → прививка → справочник собак → сохранение → разрешение → медкарта Бобика → сводка Бобика → PDF.
- [ ] Мурка → просроченная позиция → сделано → новая дата; соседние планы не изменились.
- [ ] Загрузка, ошибка с кэшем/без кэша, офлайн-сохранение без потери ввода, ошибка справочника с ручным вводом.
- [ ] Удаление записи и отмена плана с разными текстами, подтверждение выхода из изменённой формы. Удаление питомца — отдельный открытый вопрос исходной спецификации.
- [ ] Подготовить план реализации и отчёт этапа по правилам репозитория. Не считать проверку HTML-макетов проверкой приложения.

## До запуска

Согласовать спорные формулировки счётчика и ошибки веса, текст удаления питомца, решение о кнопке визита при «ВСЁ В ПОРЯДКЕ». Ветеринар должен проверить справочник: макеты не подтверждают правильность составов, интервалов или дозировок.

## Итерационная реализация

Использовать [общий план MR-01–MR-11](../../plans/medical-record/README.md). Этот файл задаёт требования к интерфейсу; отдельные файлы этапов задают порядок реализации и критерии приёмки. Начать с MR-01, не реализовывать всю медкарту одной задачей.
