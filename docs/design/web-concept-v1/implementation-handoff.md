# Передача веб-концепции на реализацию

Дата: 23 сентября 2026. **Статус: предложение на обсуждение.** Продуктовый код не изменён. Этот документ задаёт проверяемый порядок будущей работы, но не означает согласования новой навигации или закрытия этапов roadmap.

## 1. Зафиксировать объём перед началом

- [ ] Прочитать README и карту экранов этого комплекта, актуальные AGENTS.md и roadmap.
- [ ] Уточнить финальную навигацию: предлагается широкий кабинет с отдельными страницами вместо основных модальных форм.
- [ ] Сверить свежий код с перечисленными источниками: продукт развивается параллельно. Не удалять новые возможности, появившиеся после 23 сентября.
- [ ] Не переписывать API и бизнес-логику ради внешнего вида. Сохранить CSRF, auth callback/next, ограничения аккаунта и роли, начисление и списание проверок.

## 2. Перенести общую визуальную основу

- [ ] Nunito + Manrope, канва, карточки, бирюзовые действия и исходный оранжевый SVG.
- [ ] Базовые кнопки, поля, фокус, ошибки, disabled/loading. Минимальная зона касания 44 px.
- [ ] Все пять уровней срочности: имя + действие + цвет, без смешивания с брендовым оранжевым.
- [ ] Перенести прозрачные PNG в продуктовый каталог ресурсов, не ссылаться на `docs/` из рабочего приложения.
- [ ] Сохранить английскую и русскую локализации, избегать текста прямо в компонентах.

## 3. Главная и авторизация

- [ ] Главная: новый первый экран, CTA в регистрацию для гостя и к проверке/кабинету для авторизованного, три шага, ограничение «не заменяет осмотр».
- [ ] Подтвердить актуальность бесплатных проверок перед показом оффера.
- [ ] Вход, регистрация, подтверждение письма, восстановление и новый пароль: все действующие ошибки и состояния отправки.
- [ ] На всех страницах авторизации, включая ошибки и письмо, скрыть верхнюю кнопку «Войти» на desktop и mobile. Сохранить основное действие формы и ссылки под ней; на главной кнопку в шапке оставить.
- [ ] На auth-экранах только логотип и утверждённый слоган, без животных.
- [ ] Поля пароля с реальным переключением видимости; сохранить autocomplete и правила пароля из продукта.
- [ ] Между последним полем и основным действием — 24 px; разделитель «или»; три провайдера.
- [ ] Согласие при регистрации применяется к email, Google, Яндексу и Apple. Ошибка согласия видна рядом с чекбоксом, выбранное состояние не теряется.
- [ ] Сохранить callback, разрешённый next, обработку ошибки/отмены и ожидания провайдера. Реальные кнопки сверить с актуальными правилами брендов.

## 4. Кабинет и навигация

- [ ] Desktop: боковое меню «Обзор», «Питомцы», «Проверка симптомов», «История»; баланс доступен в оболочке.
- [ ] На узком экране меню превращается в нижнюю навигацию; она не перекрывает последнее действие или текст.
- [ ] До 760 px заголовки секций с действием складываются вертикально: заголовок/счётчик, затем ссылка слева, промежуток 4 px и зона касания 44 px. Не сжимать «Добавить питомца» рядом с заголовком; тот же принцип для «Вся история». Проверить 320/390 px. На desktop оставить действия справа.
- [ ] На обзоре: карточки питомцев, последние результаты, запуск проверки, переход ко всей истории.
- [ ] Первый вход, загрузка, отсутствие связи и ошибка запроса — отдельные состояния; не подменять ошибку пустым списком.
- [ ] Нулевой баланс, pending, approved, rejected и ошибка запроса дополнительной проверки соответствуют текущему сервису. Повторный запрос недоступен в pending.
- [ ] Ссылку статистики показывать только администратору. Сам URL также защищён на сервере.

## 5. Питомцы

- [ ] Сохранить создание, редактирование и удаление кошки и собаки.
- [ ] Поля: вид, имя, порода, возраст, вес, пол, кастрация/стерилизация, вакцинация, питание, образ жизни, аллергии, хронические болезни, препараты, заметки; для собаки размер и активность прогулок.
- [ ] Видовые варианты и nullable-значения брать из актуальных контрактов и словаря. Макет показывает образцы, не полный enum.
- [ ] «Заметки» написано один раз, accessible label у textarea сохранён.
- [ ] Не возвращать нижнюю ссылку «К списку». Есть навигация в шапке/оболочке и отмена.
- [ ] Сохранить валидацию, данные при ошибке, предупреждение о потере изменений и подтверждение удаления. После сохранения — понятное уведомление.

## 6. Проверка симптомов

- [ ] Если питомцев нет, показать стоящую пару и предложение добавить питомца; не отправлять общий платный запрос без профиля.
- [ ] Сначала выбор питомца и обязательное описание, затем необязательные вопросы. Сохранить ограничения 3–2000 символов из текущего сценария/контракта.
- [ ] Сохранить четыре варианта длительности и остальные текущие значения; не копировать сокращённый мобильный набор.
- [ ] Чипы признаков боли — множественный выбор без галочек; одиночные вопросы допускают отсутствие ответа. Передавать состояние для доступности.
- [ ] Перед отправкой показывать фактическую стоимость и актуальный баланс.
- [ ] Ожидание, 401, отсутствие баланса, сетевые/серверные ошибки; не отправлять дублирующую проверку повторным нажатием.
- [ ] В демо показана обычная форма без загрузки фото, как в изученном веб-UI. Если к моменту реализации фото включено в вебе, отдельно дополнить макеты и требования; не удалять уже работающий функционал.

## 7. Результат и история

- [ ] Пять срочностей с точными действиями текущего продукта. Рекомендации — только из API, никаких текстовых заглушек из макета.
- [ ] Для emergency/urgent — существующий переход к поиску клиники. Основное срочное действие видно первым и на телефоне.
- [ ] Сохранить условные блоки: причины, домашние шаги, вопросы врачу, предупреждение вида, дополнительные сведения, исходные симптомы/выборы, наблюдения по фото при наличии, дисклеймер.
- [ ] Сохранить обратную связь, её привязку к check_id, повторное редактирование/статусы согласно текущей реализации.
- [ ] История содержит питомца, дату, описание, срочность, ссылку на результат; пустая история — стоящая пара.
- [ ] Прямое открытие сохранённого результата и возврат в историю работают без зависимости от ранее открытой модалки.

## 8. Служебные и юридические страницы

- [ ] Статистика: восемь имеющихся метрик, регистрации/проверки по дням, текущие периоды; заменить демонстрационные графики реальными данными.
- [ ] Условия: сохранить действующий юридический текст целиком.
- [ ] Удаление аккаунта: сохранить публичную доступность описания, повторную авторизацию, срок из константы, квитанцию, состояние принятого запроса, ошибки/повтор. Не обещать мгновенное завершение.

## 9. Приёмка

- [ ] Сравнить с desktop-превью на 1440, затем проверить 1024 и 390 px, клавиатуру и увеличение шрифта 200%.
- [ ] Клавиатурная навигация, видимый focus, доступные имена, selected/expanded/busy; подтверждение удаления с удержанием и возвратом фокуса.
- [ ] Проверить гостевой путь: главная → регистрация/вход → питомец → проверка → результат → отзыв → история.
- [ ] Проверить возвращающегося пользователя, нулевой баланс, ошибки форм и запросов, прямые URL, RU/EN.
- [ ] Не считать превью подтверждением серверных контрактов, платежей или медицинской корректности.
- [ ] Записать фактические проверки в `docs/verification/`, по принятому в репозитории формату.

Ожидаемый результат этой работы — согласованный внешний вид поверх существующих сценариев; отклонения и новая функциональность требуют отдельного описания.
