## Что изучено

Опубликованная главная просмотрена в браузере 23 сентября. Закрытые страницы и их сценарии изучены по исходникам текущего checkout, без входа в чужой аккаунт и без создания данных. Проверка на реальном сайте ограничена главной; текущий код может опережать опубликованную версию.

Основные источники относительно корня репозитория:

- `apps/web/src/components/LandingContent.tsx`: публичная главная и её демонстрационная анкета.
- `apps/web/src/components/AppShell.tsx`, `apps/web/src/app/globals.css`: узкая оболочка кабинета, оранжевые действия, Geist/Fraunces и отдельное оформление публичных страниц.
- `apps/web/src/features/auth/AuthModal.tsx`: вход, регистрация, восстановление, Google/Яндекс/Apple, обязательное согласие при регистрации для всех способов входа.
- `apps/web/src/features/dashboard/`: питомцы, история, запуск проверки в модальном окне, запрос дополнительной проверки.
- `apps/web/src/features/pets/PetForm.tsx`: общий профиль, видовые поля собаки, здоровье, заметки и удаление.
- `apps/web/src/features/symptom-check/CheckForm.tsx`: одна веб-форма, четыре значения длительности, необязательные уточнения, множественные признаки боли, списание проверки.
- `apps/web/src/features/symptom-check/CheckResultContent.tsx`: пять уровней срочности, поиск клиники, действия, вопросы врачу, детали, предупреждение вида, наблюдения по фото при наличии данных, обратная связь.
- `apps/web/src/app/(frontend)/checks/page.tsx`, `check/[id]/page.tsx`: общая история и отдельный результат. `/check` сейчас перенаправляет в кабинет.
- `apps/web/src/app/(frontend)/account-deletion/`, `legal/page.tsx`: публичные страницы удаления и условий.
- `apps/web/src/features/admin/AdminStatisticsClient.tsx`: служебная статистика, восемь метрик и два временных графика.

## Что предлагается

**Один визуальный язык с мобильным приложением, компоновка — для браузера.**

1. На главной — ясное объяснение пользы и обычная заметная кнопка вместо круглого CTA. Пара питомцев работает как главный визуальный образ. Три коротких шага объясняют сервис. Текущий оффер «2 проверки бесплатно» сохранён из словаря сайта; перед релизом подтвердить, что он соответствует правилам начисления.
2. В кабинете — боковая навигация и широкая рабочая область. Список питомцев, последние результаты и следующее действие видны одновременно. Баланс доступен постоянно, но не конкурирует с основной задачей.
3. В авторизации — логотип и «Маленькие лапки. Большая забота», без животных. Слева короткое объяснение пользы; справа форма. На узком экране одна колонка. Подписи провайдеров полные, разделитель «или». Согласие на регистрацию сохранено и распространяется на OAuth.
4. В проверке — сначала описание своими словами, затем необязательные уточнения. Это одна веб-форма, без искусственного деления на мобильные шаги. Справа контекст выбранного питомца и пояснение результата. Чипы без галочек, доступное состояние выбора сохранено.
5. В результате — сначала срочность и требуемое действие. Длинные рекомендации занимают основную колонку, контекст и отзыв — правую. Значение срочности никогда не передаётся одним цветом. Для экстренного/срочного результата сохранён переход к поиску клиники.
6. Профиль питомца — широкая форма с логичными секциями. Видовые поля сохраняются; заметки без повторной подписи. Удаление визуально отделено от сохранения.
7. Пустые состояния используют существующие прозрачные PNG: пара в лежанке — первый питомец; стоящая пара — нет проверок/нет питомца для проверки; пушистая лапа — ожидание.

Для сравнения рассматривались три подхода: косметически перекрасить текущую узкую колонку; сделать широкий кабинет с самостоятельными страницами; сохранить модальные формы в широком кабинете. Рекомендован второй: длинные анкеты и результаты удобнее читать на странице, доступна прямая ссылка. Третий потребовал бы меньше изменений навигации, но оставил бы вложенную прокрутку. Предложенный перенос из модалок в страницы — **изменение организации интерфейса**, его нужно согласовать до продуктовой реализации.

| Desktop | Боковая панель 224 px, рабочие поля 44 px |

Экспорт: desktop 1440 px по ширине, полная высота страницы. Дополнительно проверены все экраны на 1024 и 390 px. До 760 px боковая панель заменяется нижней навигацией, колонки складываются, формы прокручиваются вместе со страницей. Нельзя переносить высоту PNG как фиксированную высоту приложения. Для браузера с увеличенным шрифтом блоки должны расти.

Все иллюстрации, шрифты и логотипы используются из `../mobile-concept-v1/assets/`, без дублирования и новой генерации. При передаче HTML нужно передавать обе папки рядом. Фото конкретного питомца этими иллюстрациями не подменяется: аватары — видовые заглушки.

## Границы и состояния

Это **предложение**, а не новый согласованный стандарт поверх действующей мобильной спецификации. Мобильные макеты не изменены.

- Нет выдуманных тарифов, оплаты, подписок, чата с врачом, календаря прививок или статистики здоровья.
- В существующей веб-форме нет загрузки фото, поэтому в концепции нет кнопки загрузки. Поля результата фото, если они есть в сохранённом ответе, нельзя потерять при реализации. Свежие изменения backend/mobile не означают наличие такого же UI в вебе.
- Добавлены самостоятельные представления «Питомцы» и «Доступные проверки» — это группировка существующих возможностей, новые URL нужно выбрать при реализации.
- Фильтры истории, поиск и выгрузка PDF не добавлялись: их нет в рассмотренном UI.
- Статистика — отдельный служебный макет; обычному пользователю ссылка на неё не показывается. Числа и графики вымышлены и помечены.
- Юридические страницы показывают только структуру. Действующий текст, сроки удаления, квитанция и состояния повторной авторизации берутся из продукта, не из сокращённого макета.
- Результаты содержат нейтральные заглушки содержательных рекомендаций: это позволяет обсуждать дизайн без придумывания медицинского ответа. Уровни и действия взяты из текущего словаря сайта.

## Прототип и проверка

Работают переходы между макетами, согласие на регистрации перед демо-OAuth, выбор чипов, аккордеоны, показ поля отзыва и имитация отправки, отмена удаления. На ожидании результат открывается по явной ссылке — таймер не имитирует время медицинского анализа. Почта, пароли, оплаты, удаления и реальные проверки никуда не отправляются. Данные форм не сохраняются при навигации; это требуется от рабочей реализации, а не от галереи.

Запуск экспорта: `node docs/design/web-concept-v1/render.cjs`. При другом окружении задать `PLAYWRIGHT_MODULE` и `CHROME_PATH`. Путь к runtime и Chrome можно изменить через эти переменные, установка в продукт не требуется.

Проверки продукта, клавиатуры, экранного диктора, серверных ошибок и OAuth выполняются отдельно при реализации. Успешная отрисовка концепции их не заменяет.
