## Перенос изменений в веб

| Изменение | Предложение и экран |
|---|---|
| Onboarding, сохранение цели | `welcome`, `pet-form`, `check`, `first-record`. Два пути; после питомца продолжается выбранный. |
| Новые рисунки | Действующие мультяшные ресурсы сайта, без повторной генерации. |
| Фото питомца | В `pet-form` — необязательная загрузка. Фото владельца должно иметь приоритет перед видовой заглушкой. В макете фото не загружено. |
| Дата рождения, приблизительный возраст, дата появления в семье | В `pet-form` отдельная компактная секция дат, переключатель точной/примерной даты. В карточке — дни вместе. Праздничные состояния отдельно не отрисованы. |
| Первые шаги с прививками и врачом | `first-steps` — дополнительный сценарий обычного добавления питомца, не обязательный шаг между onboarding и проверкой; не дублирует `first-record`. |
| Напоминания | `record` — обычное начертание, красная подпись под датой без линии, разделители и отдельное действие. Дата в примере: 20 октября, просрочка от 10 октября — 10 дней. |
| Время курса и приём | `medication`, `record` — плюс рядом со временем, «Дали», статус под дозировкой и текстовое «Отменить». |
| Календарь | `visit` — явное открытие Google Календаря, пользователь сохраняет событие сам. |
| Памятка для передержки | `memo` — просмотр и копирование текста для браузера. Расширение по сравнению с мобильным системным «Поделиться». Демонстрационные сведения, не медицинские рекомендации. |
| Понятные действия плановой записи | В `visit` основное действие «Перенести визит», выполненное событие отмечается отдельно. |

## Различия с текущим сайтом

Иллюстрации уже заменены в веб-ресурсах. У API есть поддержка новых полей и курсов; это не означает, что весь соответствующий веб-интерфейс уже реализован. В просмотренных веб-компонентах нет представленных здесь onboarding, блока приёмов и настройки времени курса. Фото и даты требуют отдельного подключения в веб-форме.

Макеты сохраняют боковую навигацию кабинета и Nunito/Manrope, кремовый фон, бирюзовые действия, оранжевый логотип. На desktop контент распределён в две колонки. Проверка симптомов остаётся веб-формой, не копией мобильных шагов.

Веб-push не обещается: текущие уведомления о приёме реализованы на телефоне. Макет предлагает редактирование времени и отметок в общем аккаунте; фактическая синхронизация с устройством требует проверки при последующей реализации.
