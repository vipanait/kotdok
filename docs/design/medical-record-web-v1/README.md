## Предложение

Сохраняем фирменный кремовый фон, белые карточки, зелёные действия, Nunito/Manrope и прозрачные аватары. Логотип один: в боковой панели на компьютере или верхней панели телефона. В навигации «Питомцы» — нейтральная лапа.

На компьютере медкарта использует пространство для двух зон. Слева — ближайшие дела и важные сведения, справа — краткая история по разделам и график. Не приходится открывать каждый раздел, чтобы понять, что происходит. Основные прививки и виды обработок вынесены рядом со списком записей.

На телефоне сайт сохраняет привычную нижнюю навигацию. Медкарта складывается в одну колонку; действия «Добавить запись» и «Для врача» закреплены над навигацией. Справочник работает внутри формы, без копирования native-шторок. Таблицы сводки становятся вертикальными записями с подписями.

## Что улучшено относительно буквального переноса приложения

- На большом экране сроки и история видны одновременно; нет длинного растянутого мобильного списка.
- В формах сохраняется удобная ширина чтения около 640 px, даже на широком мониторе.
- Просроченность объясняется словами и значком, не только цветом. Она не оформлена как экстренный медицинский результат.
- У каждой обработки своя следующая дата. «Сделано» относится к конкретной позиции.
- Пустая медкарта честно показывает сведения из анкеты без выдуманных дат.
- Сводку можно распечатать или сохранить через печать браузера, без установки приложения.

## Состав и ограничения прототипа

Есть заполненные и пустые разделы, сделанные и запланированные записи, ручной ввод, справочник кошки/собаки, завершение срока, ошибки загрузки/сохранения, просмотр и подтверждение удаления, анкета, сводка и пример A4. Набор экранов и имена PNG перечислены в screen-map.md.

Демонстрационные данные зафиксированы на 24 сентября 2026 для сравнения с мобильными макетами. Препараты, дозировки и записи являются примерами из спецификации, не ветеринарной рекомендацией и не источником production-каталога.

Прототип локальный: выбор препарата, добавление позиций, переключатели, подтверждения и поиск демонстрируют поведение, но сохранение показывает сообщение и не обращается к API. Переключатели периода графика не пересчитывают демонстрационные точки. Валидация браузера не заменяет contracts. Отдельные переходы используют заранее заполненные примеры вместо переноса введённых значений. Управление фокусом, полноценная клавиатурная модель combobox, защита несохранённых данных, все серверные ошибки и реальные переходы между сущностями обязательны в реализации, а не заявлены готовыми в макете.

`print` — пример компоновки A4. Печатное поведение реальной многостраничной сводки принимается отдельно на MW-07. Основной веб-дизайн сайта остаётся в соседнем web-concept-v1.

## Скриншоты

`screens/<id>.png` — весь экран при ширине 1440 px; `<id>-390.png` — видимая область 390 × 844; `<id>-390-full.png` — вся длинная страница. На полном снимке закреплённые элементы перенесены вниз страницы только для экспорта, чтобы не перекрывать середину длинной формы. Для проверки реального положения при прокрутке используйте живой прототип и снимки видимой области.

`render.cjs` воспроизводит снимки локальным Chrome, проверяет 320/390/1024/1440 px, изображения, JavaScript и базовые действия. Пути runtime заданы для текущей рабочей машины; при переносе замените на установленный Playwright/Chrome. Результат — render-report.json. Это проверка дизайна, не end-to-end тест готовой функции.

## Сохранённые записи

Прививки и обработки из списка открываются для просмотра. У выполненной записи нет редактирования. У плана «Изменить» ведёт к форме с его данными, «Отмена» возвращает к нему. Для планов выполнение выделено в отдельное действие «Сделано». Сохранение остаётся демонстрационным и не обращается к API.
