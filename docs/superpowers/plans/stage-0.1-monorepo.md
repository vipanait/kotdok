# Исполнимый план этапа 0.1 — монорепозиторий и независимые сборки

Источник требований: [дорожная карта](../../mobile-api-plan.md), раздел «Этап 0.1». Отчёт: `docs/verification/stage-0.1.md`.

База: коммит `ba9dd58` («Point the stage 0 run record at the commit that holds the work»), ветка `stage-0-baseline`.

Принцип этапа: **механический перенос**. Поведение сайта не меняется, новых бизнес-тестов не пишем — приёмкой служат существующие тесты и сравнение поведения. Новые тесты допустимы только для нового поведения (например, проверка отсутствия серверных секретов в мобильном бандле).

## Целевая структура

```
apps/web/          Next.js: src, public, tests, next.config.ts, tsconfig.json,
                   eslint.config.mjs, postcss.config.mjs, vitest*.config.mts,
                   .env.test, .env.integration
apps/mobile/       Expo: app.json, tsconfig.json, минимальный экран
packages/contracts/  каркас (реальные схемы — этап 1)
packages/shared/     каркас (перенос кода — этап 1)
supabase/          миграции, config.toml (остаются в корне)
docs/              документы (остаются в корне)
```

Корневой `package.json` — только workspaces и агрегирующие скрипты, без зависимостей приложения. Единый `package-lock.json` в корне.

## Входные и выходные контракты

- Вход: работающее дерево этапа 0; все пять проверок проходят с кодом 0.
- Выход: те же пять проверок проходят из `apps/web`; `npm ci` из чистой копии не меняет lockfile; Expo экспортирует JS для iOS и Android; импорт из обоих общих пакетов разрешается в обоих приложениях.
- Общие пакеты не импортируют Next.js, серверные SDK и DOM. На этом этапе они пустые каркасы, поэтому проверка ограничивается их зависимостями и настройкой сборки.

## Что этот этап не делает

Не переносит бизнес-код в общие пакеты (этап 1), не создаёт контракты API (этап 1), не добавляет авторизацию и экраны мобильного приложения (этапы 4+), не выпускает подписанные сборки (этап 4), не обновляет фреймворки.
