# Mobile Due Dates — Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Переработать мобильный блок «Сроки» по выбранному пользователем варианту «Сначала просроченное» с компактной кнопкой «Отметить» видимой высотой 36 dp.

**Architecture:** Изменить представление существующих DueRow и списков сроков в Expo-приложении. Сохранить данные, сортировку, вычисление сроков и навигацию; группировать уже вычисленные состояния только для отображения.

**Tech Stack:** React Native, Expo, TypeScript, существующие компоненты Icon/Text и локализация RU/EN.

**Spec:** Раздел «Согласованный дизайн» ниже; эталоны `docs/design/due-priority/due-390.png` и `due-320.png`. `mockup.html` — исходник выбранного визуального варианта, `preview.html` — открываемый браузерный просмотр. Пути в документе относительно корня репозитория.

## Global Constraints

- Прочитать применимые AGENTS.md и актуальные файлы перед правками; учесть параллельные изменения рабочего дерева.
- Область задачи — мобильное приложение. Веб, API, БД и модель медицинских записей не изменять.
- В исходном DueRow просрочка намеренно нейтральная; новый выбор пользователя заменяет это визуальное решение на спокойный терракотовый акцент. Это индикатор пропущенной даты, а не медицинской срочности. Не добавлять тревожные формулировки и не менять клинические категории. Обновить устаревший комментарий в компоненте.
- Сохранить dueItems, dueStatus, marksFromRow, recordRoute, doneRoute и календарную арифметику. Не вычислять дни заново в JSX.
- Сохранить кнопку «Отметить» и существующий переход onDone. Галочка — декоративная часть кнопки; она не означает, что запись уже выполнена. Не переносить демонстрационное переключение на «Отмечено» из прежних вариантов.
- Макет содержит данные исходного скриншота: «Просрочено на 9 дней», «Завтра · 20 октября». Это зафиксированный пример, не текущие даты. В приложении все даты и подписи динамические.
- Не заменять существующую тему и типографику целиком. Добавить только локальные стили/семантический токен, необходимый блоку.

## Согласованный дизайн

Одна белая карточка «Сроки» на существующем бежевом фоне, скругление примерно 22 dp, внутренние отступы 20 dp. Заголовок около 25 dp, Nunito, 800.

Просроченная запись:
- Слева вертикальная линия шириной 3 dp, цвет `#A44836`; от линии до содержимого 14 dp.
- Сверху текст существующего overdue-статуса, тот же цвет, 12 dp, 700. Статус читается словами, цвет только дополняет его.
- Ниже строка с иконкой типа события слева и названием справа. Область иконки 36 × 36 dp, мягкая подложка `#F4F0E8`, скругление 11 dp; сам значок около 20 dp. Промежуток 12 dp.
- Название: 16 dp, 700, основной цвет текста, перенос по словам разрешён.
- Под названием: «Плановая дата · 10 октября», размер 13 dp, спокойный цвет `#716B61`. Использовать локализованную абсолютную дату из status.day. Для давно просроченного статуса, уже содержащего дату (`dated: true`), повторную строку «Плановая дата» не показывать.
- Под датой компактная зелёная кнопка с галочкой и текстом «Отметить», выровненная по началу названия, а не по иконке. Отступ сверху 12 dp, смещение относительно строки 48 dp (36 + 12).
- Видимая высота кнопки **36 dp**, ширина по содержимому, скругление 10 dp, горизонтальные отступы 13 dp. Цвет `#0B6B5E`, белый текст 13 dp / 700 и галочка 16 dp, промежуток 7 dp.
- Эффективная область нажатия минимум 44 × 44 dp: `hitSlop` минимум 4 dp сверху/снизу либо отдельная область нажатия высотой 44 dp с визуальной кнопкой 36 dp внутри. Проверить, что границы родителя не обрезают hitSlop и области соседних действий не пересекаются. При крупном системном шрифте разрешить рост кнопки, не обрезать текст ради 36 dp.

После просроченных записей — отступ около 23 dp и небольшой заголовок группы «БЛИЖАЙШЕЕ» (11 dp / 700, letter spacing около 1 dp, приглушённый цвет). Далее обычная строка: иконка, название, строка «Завтра · 20 октября», справа шеврон. Относительный срок выделен зелёным, абсолютная дата спокойным цветом. Если такая запись markable по существующим правилам, сохранить компактную кнопку, не заменять её шевроном.

Группы формируются по status.tone: overdue → soon → later. Для later использовать «Позже». Пустые группы и их заголовки не показывать. При отсутствии просроченных сразу показывать имеющиеся группы. Внутри группы сохранять существующий порядок. На медкарте сначала применить существующий лимит DUE_ON_RECORD, потом сгруппировать видимые записи; сохранить ссылку «Все сроки» и её счётчик. На странице «Все сроки» показать все записи с тем же оформлением. Для нескольких просроченных записей повторять оформление каждой записи с отступом между ними 20 dp.

## Task 1: Реализовать выбранное отображение

**Interfaces:** Сохранить props DueRow (`due`, `status`, `markable`, `onOpen`, `onDone`). Новый `DueList({ items, today, onOpen, onDone })`: `items: readonly Due[]`, `today: string`, `onOpen: (due: Due) => void`, `onDone: (due: Due) => void`. Компонент использует useText, dueStatus и marksFromRow, разделяет уже отсортированные записи по tone. Он не загружает данные, не обрезает список и не выполняет навигацию сам.

- [ ] Прочитать текущие DueRow, оба экрана, `due.ts`, тему, компоненты Text/Icon и соответствующие тесты.
- [ ] В RU/EN добавить подписи в medicalRecord: `dueUpcoming` — «Ближайшее» / «Upcoming»; `dueLater` — «Позже» / «Later»; `duePlannedDate` — «Плановая дата» / «Planned date». Существующие формулировки overdue и markDue переиспользовать.
- [ ] Перестроить DueRow по разделу дизайна. Сохранить открытие записи и отдельное действие «Отметить». Нажатие кнопки не должно одновременно вызывать onOpen; предпочтительно разделить Pressable заголовка/содержимого и кнопки как соседние элементы. Обеспечить отдельные понятные accessibilityLabel.
- [ ] Создать DueList по указанному интерфейсу. Заголовки групп показывать только при наличии записей. Overdue-записи уже имеют индивидуальную подпись статуса, дополнительный заголовок «Просроченное» не нужен.
- [ ] Заменить циклы строк на двух экранах на DueList, передав существующие обработчики маршрутов. На медкарте передать `due.slice(0, DUE_ON_RECORD)`, на полном экране — все записи. Сохранить загрузку, ошибки, пустые состояния и счётчик.
- [ ] Сверить выбранный вариант с двумя эталонными скриншотами. Не копировать CSS/HTML в React Native: размеры перенести в dp и существующую систему компонентов.

## Review Focus

- Несколько просроченных записей, только ближайшие, только поздние, пустой список: нет пустых заголовков и потерь записей.
- Сегодня, завтра, вчера, давно просрочено (`dated: true`), дата другого года: правильные динамические подписи без повторения даты.
- Длинные названия, RU/EN, узкий экран и увеличенный шрифт: ничего не обрезается, кнопка остаётся доступной.
- onDone и onOpen: каждое нажатие вызывает только нужный переход; markable сохраняет прежний смысл для вакцинаций, обработок и визитов.
- Видимая кнопка 36 dp при обычном шрифте, реальная область касания минимум 44 dp, в том числе на Android.
