# «Можно ли это питомцу» — дизайн

Дата: 13 ноября 2026. Ветка: `claude/can-pet-eat-f35f72`. План реализации: [../plans/2026-11-13-pet-safety.md](../plans/2026-11-13-pet-safety.md).

## Зачем

Лапку открывают, когда питомцу плохо. У конкурентов (PawLife, SafePet AI, Voyage) есть справочник «можно ли это питомцу», и он даёт повод зайти в приложение, когда питомец здоров. У нас такого раздела нет, зато есть шесть SEO-страниц `/otravlenie`, с которыми он стыкуется: человек ищет «можно ли собаке виноград», попадает на сайт, а дальше — в приложение.

Пользователь вводит продукт, растение, лекарство или бытовое вещество и получает для своей кошки или собаки: вердикт, почему так, и что делать, если питомец это уже съел, — с переходом в проверку симптомов.

## Цели

1. Ответ на известный запрос — мгновенный, одинаковый при каждом обращении и проверяемый по файлу в репозитории.
2. Ни один запрос не заканчивается тупиком: чего нет в справочнике, на то отвечает ИИ, и это видно.
3. Ошибка в безопасную сторону: при сомнении вердикт строже.
4. Раздел заметен в приложении и приводит трафик из поиска.

## Чего не делаем в первой версии

- Фото состава корма — отдельный этап после распознавания документов в соседней сессии.
- Раздел в веб-кабинете (после входа). На сайте только публичные страницы.
- История запросов на сервере. Последние запросы приложение помнит на телефоне.
- Экран в админке со списком запросов-промахов. Промахи копятся в таблице, смотреть их можно запросом.
- Персональный разбор ИИ под болезни питомца.
- Дозы, «сколько граммов можно», расчёты по весу.

## Чего нельзя допустить

- «Можно» про то, что опасно. Это главный риск функции.
- Текст, похожий на назначение лечения: дозы, препараты, «дайте», «вызовите рвоту» (App Store 1.4.1).
- Ответ ИИ, который выглядит как проверенная запись справочника.
- Заявление, что данные проверил ветеринар: его не было.

## Ограничения

- Справочник препаратов `health_catalog` ветеринаром не проверен; здесь та же ситуация. Правила авторства — как у SEO-страниц (`apps/web/content/README.md`): пишет модель, дважды проверяют агенты, публикует владелец.
- `packages/*` остаются переносимыми: без Next.js, серверных SDK и DOM.
- Локальный Supabase общий для всех worktree: следующая свободная метка миграции, без `db reset`.
- Экран результата проверки симптомов и медкарту не трогаем: их правят соседние сессии.
- Магазинные сборки приложения старше этой функции продолжают работать: меняются только новые маршруты API.
- Merge в `main` и выпуск приложения делает владелец.

## Подходы

| | Как работает | Плюсы | Минусы |
|---|---|---|---|
| **Гибрид (выбран)** | Справочник в репозитории даёт вердикт для известных позиций, ИИ с базой знаний отвечает на остальное с пометкой | Частые запросы предсказуемы и бесплатны для нас, тупиков нет | Два пути ответа, справочник нужно вести |
| Только справочник | Нет в списке — «пока не знаем» | Самый предсказуемый | Каждый промах — тупик |
| Только ИИ | Каждый ответ генерирует модель по `vet_knowledge` | Быстро сделать | Вердикт может меняться от раза к разу, каждый вопрос стоит денег, нет страниц для поиска |

Владелец выбрал гибрид 13 ноября 2026.

## Решения владельца (13 ноября 2026)

1. Источник: гибрид.
2. Нет в справочнике: ответ ИИ с пометкой; без опоры в базе знаний «Можно» не выдаётся; запрос записывается для пополнения.
3. Питомец: вид + простые пометки (совпадение с аллергией из анкеты, общая строка при хронических болезнях). Без ИИ.
4. Цена: бесплатно; ответы ИИ — около 10 в сутки на аккаунт.
5. Приложение: четвёртая вкладка.
6. Сайт: публичные SEO-страницы из того же справочника, без раздела в кабинете.
7. Фото состава: позже.
8. Объём: около 120 позиций.
9. Лекарства для людей — всегда «Опасно» с фиксированной строкой «не давайте без назначения врача». Бытовые вещества — «Опасно» или «Малый риск». «Можно» бывает только у продуктов, «Безопасно» — только у растений.

Всё ниже, что не входит в эти восемь пунктов, — решения исполнителя; они помечены «(решение исполнителя)».

## Как это устроено

### Справочник

Один JSON-файл — одна позиция: `apps/web/content/safety/<slug>.json`. Схема Zod — `apps/web/src/features/safety/schema.ts`.

| Поле | Содержание |
|---|---|
| `slug` | латиница и дефисы: `vinograd`, `shokolad` |
| `category` | `food`, `plant`, `medicine`, `household` |
| `name` | `{ ru, en }`: «Виноград» / “Grapes” |
| `aliases` | `{ ru: [], en: [] }`: другие названия и словоформы, по которым позицию находят («изюм», «виноградина», «коринка») |
| `bySpecies.cat`, `bySpecies.dog` | оба обязательны; см. ниже |
| `firstSteps`, `avoid` | `{ ru, en }` списки: что сделать сразу и чего не делать, если съел. Обязательны, если хоть у одного вида `ifEaten` ≠ `none` |
| `toxinSlug` | необязательно: slug страницы `/otravlenie`, если она есть |
| `sources` | 1–3 источника: название, `url` — только если адрес точно существует |
| `review` | как у SEO-страниц: `draft` → `agent_reviewed` → `published` |

Раздел вида:

| Поле | Содержание |
|---|---|
| `verdict` | `safe`, `caution`, `danger` |
| `summary` | `{ ru, en }`, одно-два предложения: главный ответ |
| `why` | `{ ru, en }`: почему так. Для `caution` — при каких условиях допустимо (без косточек, без соли, изредка), без граммов |
| `signs` | `{ ru, en }` список признаков; обязателен для `danger`, для остальных может быть пустым |
| `ifEaten` | `call_now` (звонить в клинику, не ждать признаков), `watch` (наблюдать, при признаках — проверка симптомов), `none` |

Правила, которые проверяют тесты:

- `danger` ⇒ `ifEaten: call_now`. `safe` ⇒ `ifEaten: none`.
- `category: medicine` ⇒ у обоих видов только `danger`. `category: household` ⇒ `safe` запрещён.
- Один и тот же alias не принадлежит двум позициям (после нормализации).
- Запрещённые слова из `FORBIDDEN_WORDS` SEO-страниц и их английские пары (`diagnos`, `prescrib`, `mg/kg`, `dosage`) — нигде в текстах.
- Про рвоту — отдельная новая проверка (у SEO-страниц это правило только в README): «вызыв… рвот…» допустимо лишь в строке со словами «только по указанию врача», “induce vomiting” — лишь с “unless a vet tells you to”.
- У каждой позиции заполнены оба языка.

Русский и английский — в одном файле (решение исполнителя): приложение работает на двух языках, источники английские, а раздельные файлы разошлись бы по вердиктам. Публичные страницы — только русские, как остальной контент.

Что значит вердикт. Вопрос, на который отвечает карточка, зависит от категории: продукт — «можно ли этим кормить», растение — «опасно ли, если погрызёт», лекарство и бытовое вещество — «опасно ли, если проглотит». Поэтому подпись вердикта зависит от категории (решение владельца №9, подписи — решение исполнителя):

| Категория | `safe` | `caution` | `danger` |
|---|---|---|---|
| `food` | Можно / Safe to eat | С осторожностью / With caution | Нельзя / Not safe |
| `plant` | Безопасно / Non-toxic | С осторожностью / With caution | Опасно / Dangerous |
| `household` | — (запрещён) | Малый риск / Low risk | Опасно / Dangerous |
| `medicine` | — (запрещён) | — (запрещён) | Опасно / Dangerous |

- `safe` у продукта: допустимо как лакомство в небольшом количестве; не замена корму.
- `caution` у продукта или растения: допустимо при условиях либо вредно при регулярном контакте.
- «Малый риск» у бытового вещества: небольшое количество обычно не опасно, но давать нельзя; `ifEaten: watch`.
- У каждого лекарства под вердиктом фиксированная строка из словаря: «Лекарства для людей не давайте питомцу без назначения врача» / “Do not give human medicines to a pet unless a vet prescribes them”. Тексты лекарств не описывают, как и сколько давать.
- `unknown` — «Нет данных / No data» — только в ответах ИИ: надёжных сведений нет, не давайте.

### Откуда данные и как они проверяются

Источники: списки ASPCA Animal Poison Control (токсичные и нетоксичные растения, еда со стола), Merck/MSD Veterinary Manual (токсикология), Pet Poison Helpline, Cornell Feline Health Center и Cornell Riney Canine Health Center. Автор-модель работает по этим источникам, а не по памяти, и называет в `sources` те, на которые опирался.

Процесс — как у SEO-страниц, плюс правила для вердикта:

1. Черновик пишет модель (`draft`).
2. Два независимых круга проверки агентами с разной разбивкой позиций. Второй круг сверяет вердикты заново по источникам, а не по черновику. Поле `review` остаётся как у статей (один `reviewedBy`); то, что кругов было два, фиксирует отчёт SAFE-06, как это было с SEO-страницами.
3. Источники расходятся или данных по виду мало — ставится более строгий вердикт. `safe` требует явной опоры хотя бы в одном источнике из списка; иначе `caution`.
4. Владелец публикует: `published`. Production (сайт и API) показывает только `published`; предпросмотр и `next dev` — и черновики.

Раздел «О материалах» на сайте и подпись в приложении говорят то же, что и сейчас: тексты готовит ИИ по ветеринарным источникам, ветеринар их не подписывал.

Состав на 120 позиций (решение исполнителя; список — в плане): около 60 продуктов, 30 растений, 30 лекарств и бытовых веществ. Шесть существующих тем `/otravlenie` входят в справочник и ссылаются на свои страницы.

### Поиск

Чистая функция в `packages/shared/src/safety/match.ts` — ею пользуются сервер, приложение и хаб на сайте.

- Нормализация: нижний регистр, `ё → е`, пунктуация и повторные пробелы убираются, обрезка до 80 знаков.
- Точное совпадение с названием или alias — позиция найдена.
- Подсказки при вводе: совпадение по началу слова, затем по вхождению.
- Опечатки: расстояние Левенштейна 1 для слов от 5 букв. «Шокалад» находит шоколад.
- Словоформы закрываются списком `aliases`, а не морфологией.
- Ничего не нашлось — предлагается спросить ИИ.

### Пометки под питомца

Чистая функция в `packages/shared/src/safety/pet-notes.ts`, считает сервер.

- **Аллергия.** Каждая строка `pet.allergies` нормализуется; если она совпадает с названием или alias позиции (или alias входит в неё целым словом) — пометка «У Барсика в анкете указана аллергия: курица». Показывается над вердиктом и при `safe`, и при `caution`.
- **Хронические болезни.** Если `pet.chronic_conditions` не пуст и вердикт не `danger` — строка «У Барсика указаны хронические болезни. Новые продукты лучше сначала обсудить с врачом.» Сами болезни не анализируются.
- Больше ничего из анкеты не читается.

### Ответ ИИ

Только когда поиск ничего не нашёл и пользователь нажал «Спросить ИИ».

- Вход: запрос до 80 знаков и вид (из питомца или выбранный вручную). Анкета питомца в модель не передаётся.
- Сервер ищет в `vet_knowledge` (`search_vet_knowledge`, фильтр по виду) и передаёт модели найденные фрагменты. Текст запроса — данные, а не инструкция: так и сказано в системном промпте.
- Модель возвращает JSON: `recognized`, `category`, каноническое название предмета на русском и английском, `verdict`, `title`, `summary`, `why`, `signs`, `if_eaten`.
- Серверные предохранители:
  - каноническое название, которое вернула модель, ищется в справочнике; нашлось — пользователь получает запись справочника, а не ответ ИИ («изюмчик» → виноград);
  - `category: medicine` ⇒ вердикт `danger`; `category: household` и `safe` ⇒ `unknown`;
  - ни один фрагмент не прошёл порог сходства ⇒ `safe` понижается до `unknown`;
  - `recognized: false` (не продукт/растение/вещество, просьба о лечении, бессмыслица) ⇒ ответ «Не удалось понять, что это. Назовите продукт, растение или вещество.»; в кэш не пишется;
  - в тексте нашлось запрещённое слово ⇒ тексты заменяются стандартными, а вердикт только ужесточается, никогда не смягчается: `danger` остаётся `danger` с `call_now`, `safe` и `caution` становятся `unknown`, а `call_now`, если его назвала модель, сохраняется (уточнено 13 ноября 2026 после ревью SAFE-03);
  - `danger` ⇒ `if_eaten: call_now` независимо от того, что сказала модель.
- `firstSteps` и `avoid` в ответе ИИ — не от модели, а фиксированные тексты на двух языках, один набор для всех категорий: позвонить в клинику, убрать остатки, сохранить упаковку, не вызывать рвоту без указания врача, не давать «антидоты». Таких текстов в проекте ещё нет (у страниц `/otravlenie` они свои на каждой странице) — их пишет исполнитель в `ask-language.ts`, и они проходят те же два круга проверки, что и справочник.
- Модель и клиент OpenAI — те же, что в проверке симптомов; таймаут 30 секунд, одна попытка, `maxDuration` маршрута 60.

Кэш и журнал промахов — одна таблица `safety_ai_answers` (решение исполнителя): ключ `(query_key, species, locale)`, ответ `jsonb`, счётчик обращений, даты первого и последнего. Без связи с пользователем, поэтому удаление аккаунта её не касается. Повторный запрос в течение 30 дней отдаётся из кэша и лимит не тратит. Таблица закрыта от `anon` и `authenticated`, пишет сервер.

Лимит: `safety_ask` — 10 вызовов модели за 24 часа на аккаунт, через существующий `consume_rate_limit`. Ответ из кэша лимит не тратит. Нераспознанный запрос и сбой модели попытку тратят: модель уже вызвана. Остаток лимитер умеет сообщать только при трате, поэтому до первого вопроса приложение показывает «до 10 ответов ИИ в сутки», а точный остаток — после ответа.

### API

Все маршруты — `withApiAuth`, как остальной v1. Контракт — `packages/contracts/src/safety.ts`, попадает в OpenAPI.

| Маршрут | Что отдаёт |
|---|---|
| `GET /api/v1/safety/index` | Лёгкий список для подсказок: `slug`, `category`, `name`, `aliases`, вердикт по каждому виду — на языке аккаунта |
| `GET /api/v1/safety/items/{slug}?pet_id=` | Позиция целиком на языке аккаунта; с `pet_id` — раздел вида питомца первым и `pet_notes`. Чужой или удалённый питомец — `not_found` |
| `POST /api/v1/safety/ask` | Тело `{ query, pet_id }` или `{ query, species }`. Сначала ещё раз ищет в справочнике (если нашлось — `{ source: 'catalog', slug }`), иначе ответ ИИ `{ source: 'ai', …, remaining_today }`. Ошибки: `rate_limited`, `bad_request`, `not_found` |

### Приложение

Четвёртая вкладка между «Проверка» и «Профиль»: маршрут `app/(tabs)/safety/`, подпись «Можно ли?» / “Safe?” (решение исполнителя), своя иконка.

Главный экран вкладки:

```
Можно ли это питомцу?
[ Барсик ▾ ]                       ← питомец; без питомцев — «Кошка | Собака»
┌──────────────────────────────┐
│ 🔍 Виноград, лилия, ибупрофен │
└──────────────────────────────┘
Недавние:  шоколад · авокадо
Часто спрашивают
  Продукты   Растения   Лекарства   Быт
  ● Шоколад              Нельзя
  ● Виноград и изюм      Нельзя
  ● Морковь              Можно
```

При вводе список сужается до подсказок. Если совпадений нет:

```
«драконий фрукт» нет в справочнике
[ Спросить ИИ ]      до 10 ответов ИИ в сутки
```

Карточка позиции:

```
‹ Виноград и изюм                    для Рекса (собака)
┌─ НЕЛЬЗЯ ───────────────────────────┐
│ Может вызвать отказ почек.         │
│ Безопасного количества нет.        │
└────────────────────────────────────┘
⚠ У Рекса в анкете указана аллергия: …        ← если совпало
Почему
  …
Признаки
  • рвота в первые часы …
Если Рекс уже съел
  Сразу позвоните в клинику, не ждите признаков.
  • уберите остатки …
  Чего не делать
  • не вызывайте рвоту сами — только по указанию врача
  [ Проверить симптомы ]
Для кошек: Нельзя ›                            ← второй вид свёрнут
Источники: ASPCA …, MSD …
Лапка — информационный инструмент. Не является ветеринарным
диагнозом и не заменяет осмотр специалиста.
```

Карточка ответа ИИ — та же, но с плашкой «Ответ ИИ, не из справочника» под заголовком и без раздела источников.

Переход в проверку симптомов. Кнопка «Проверить симптомы» открывает вкладку «Проверка» с выбранным питомцем и подставленным началом описания: «Съел(а): виноград. » — дальше человек дописывает сам. Проверка идёт по обычным правилам и стоит кредит; под кнопкой это сказано. Если на форме проверки уже лежит несохранённый черновик, он не затирается: приложение спрашивает, заменить ли его. Правится только форма проверки (`check/index.tsx` и `check-draft.ts`), экран результата не трогается. Если питомцев нет (выбран вид вручную), вместо кнопки — «Добавьте питомца, чтобы проверить симптомы», она ведёт на вкладку «Проверка», где уже есть свой сценарий без питомца; текст не подставляется.

- `ifEaten: call_now` — раздел «Если уже съел» раскрыт, первой строкой «Сразу позвоните в клинику», кнопка «Проверить симптомы» вторична.
- `ifEaten: watch` — «Наблюдайте. Если появятся признаки — проверьте симптомы», кнопка есть.
- `ifEaten: none` — раздела нет.

Индекс справочника приложение кэширует (как остальные запросы через `query-cache`), поэтому подсказки работают сразу. Недавние запросы — на телефоне, до десяти, привязаны к аккаунту.

### Сайт

Группа `app/(content)`, статические страницы без сессии, как `/otravlenie`.

- `/mozhno-li` — хаб: поиск по справочнику в браузере (тот же `match.ts`, индекс вшит в страницу), позиции по категориям.
- `/mozhno-li/<slug>` — страница позиции: «Можно ли кошкам и собакам виноград?», разделы по видам, «если уже съел», источники, ссылка на `/otravlenie/<slug>` при `toxinSlug`, призыв проверить для своего питомца в приложении. Одна страница на позицию, а не по странице на вид: так уже решено для отравлений, и тексты для видов не дублируются.
- Страницы `/otravlenie/<slug>` получают обратную ссылку на позицию справочника.
- `sitemap.ts` — только `published`. Новый сегмент `mozhno-li` добавляется в `CONTENT_SEGMENTS` (`src/shared/content-paths.ts`, оттуда берётся CSP) и отдельно в регулярное выражение matcher'а в `proxy.ts`. Метаданные — через `publicPageMetadata()`.
- JSON-LD: `FAQPage` из вопросов «Можно ли кошке …?» / «Можно ли собаке …?» с `summary` в ответе.

## Порядок выпуска

Production отдаёт только опубликованные позиции, а публикует владелец. Приложение с новой вкладкой выпускается после публикации справочника. На случай, если порядок нарушится, вкладка при пустом индексе показывает «Справочник скоро появится» и поле вопроса к ИИ, а не пустой экран (решение исполнителя).

- Иконка вкладки и вёрстка — в стиле существующих экранов.

## Открытые риски

- **Достоверность.** Ветеринар справочник не видел. Смягчение: два круга проверки по первичным источникам, строгий вердикт при расхождении, честная подпись. Если владелец привлечёт ветеринара, у `review` появится `reviewedBy: "vet"` — схема это допускает расширением.
- **Английские тексты** проверяются теми же агентами, носитель языка их не читал.
- **Четыре вкладки** на узких Android-экранах: подпись «Можно ли?» короткая, но проверить на Xiaomi Pad и маленьком телефоне.
