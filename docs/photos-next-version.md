# Фотографии: отложены до следующей версии

Владелец вывел фотографии из объёма этой версии **10 сентября 2026**. Здесь лежит
то, что было написано для них в дорожной карте, чтобы работа не переписывалась
заново, когда до них дойдёт очередь.

Ничего из этого не входит в приёмку текущей версии и не считается долгом.

## Где сейчас загрузка фото

Отключена в продукте, и была отключена до этого решения. Веб-форма её не
предлагает, `/api/symptom-check` принимает только JSON и отвечает `400` на
`multipart`. Причина — пункт 0.1 открытых вопросов: фотографии шли внутри тела
запроса, а Vercel обрывает тело крупнее 4.5 МБ до вызова функции.

Значит, у пользователей ничего не ломается: функции нет, а не она сломана.

Серверная поддержка фотографий в `analyze-symptom-check.ts` сохранена и ждёт
`upload_id`. Её не удаляем: она ничего не стоит, пока в анализ не приходят
идентификаторы загрузок.

## Что придётся сделать, когда вернёмся

Нумерация сохранена от прежнего этапа 6, чтобы старые отчёты и ссылки не
разъехались. Пункты 6/04–6/10 остались в дорожной карте: они про деньги и
надёжность задач, а не про фотографии.

- **6/01.** Загружать фото в приватное временное хранилище по ограниченному
  разрешению. Проверять владельца, число файлов, фактический формат, размер и
  срок действия; не принимать произвольный URL для серверной загрузки.

  **Приёмка:** Валидный файл владельца принимается; чужой/просроченный upload,
  лишний файл, неверный MIME и произвольный URL отклоняются до AI; анонимное
  чтение объекта запрещено.

- **6/02.** Сервер выдаёт `upload_id`, привязанный к владельцу и неизменяемому
  объекту; анализ принимает эти ID. Повторная подмена объекта после проверки
  запрещена. Незавершённая/просроченная загрузка не резервирует кредит.
  Декодирование проверяет не только MIME, но и предел разрешения изображения.
  Очистка не удаляет файлы активной задачи до её завершения или предельного срока.

  **Приёмка:** Попытка перезаписи объекта и изображение сверх лимита пикселей
  отклоняются; незавершённый upload не списывает кредит; с управляемыми часами
  очистка сохраняет активный файл и удаляет просроченный.

- **6/03.** На телефоне сжимать/нормализовать фото, включая HEIC с iPhone;
  согласовать лимиты с хостингом и AI-провайдером. Фотографии не хранятся: файл
  живёт только на время анализа и удаляется сразу после его завершения, брошенная
  загрузка — по истечении срока действия разрешения (решение владельца, пункт 1.6
  открытых вопросов).

  **Приёмка:** Реальные HEIC/JPEG/PNG с обеих ОС преобразуются в допустимый
  размер и читаются AI; граничные размер/число файлов проверены; после
  завершённого анализа объекта в хранилище больше нет, брошенная загрузка
  удаляется по истечении срока.

Вручную к этим трём: реальные фото iPhone/Android, слабая сеть, отказ в
разрешении камеры, разрыв загрузки.

## Что тянется за этим решением

| Что | Как сейчас |
| --- | --- |
| `POST /api/v1/uploads` | Из карты маршрутов версии убран; вернётся вместе с 6/01 |
| Приватное хранилище | Не заводится. Это была единственная новая инфраструктура MVP |
| Разрешение камеры и фотогалереи | В магазинных материалах (11/02) описывать нечего: приложение их не просит |
| Удаление объектов Storage при удалении аккаунта (8/08) | Остаётся: в Storage лежат объекты, не связанные с этой функцией. Проверять на реальном bucket |
| Лимит тела запроса Vercel (0.1) | Остаётся закрытым отключением загрузки |
| Квоты и TTL загрузок на этапе 1 | Не фиксируются в этой версии |
