# Веб-версия «Лапки» — план реализации

> **Для исполнителей:** выполняйте план по этапам через `superpowers:executing-plans`; при явно выбранной работе субагентами — через `superpowers:subagent-driven-development`. Отмечайте выполненные пункты. Эта инструкция передаётся отдельным агентам; её создание не означает, что реализация уже началась.

**Цель:** перенести доработки от 20 октября в действующий веб-кабинет и реализовать девять экранов с адаптацией для настольного и мобильного браузера.

**Архитектура:** расширять существующие Next.js-страницы, компоненты и API-клиент. Использовать действующие контракты и серверные операции; чистую общую логику при необходимости выделять в `packages/shared`, без зависимости от Expo, Next.js, DOM и серверных SDK. Сайт и приложение должны читать и менять одни данные, а не вести отдельные локальные копии записей.

**Стек:** npm workspaces, Next.js 16.3.8, React 19.2.4, TypeScript, Vitest — версии сверены при подготовке, перед работой проверить актуальный package.json.

**Дизайн:** [описание](../design/web-update-2026-10-20/README.md), [просмотр макетов](../design/web-update-2026-10-20/index.html), [стили макетов](../design/web-update-2026-10-20/style.css). HTML — визуальный прототип, не готовая архитектура приложения.

На desktop сохранить боковую навигацию кабинета и двухколоночную композицию. В узком браузере — одна колонка и нижняя навигация. На длинных PNG закреплённое меню может оказаться посередине изображения из-за full-page capture: не переносить его в середину документа, оно закреплено у края viewport. Контент и действия не должны скрываться за ним или клавиатурой.

Ориентиры проверки: 1440, 1024, 768, 390 и 320 px. На промежуточной ширине переключать колонки по доступному месту; не сжимать поля и кнопки до нечитабельности. Точные демодаты не копировать: относительные сроки рассчитываются по текущему дню пользователя.

## Особое внимание при проверке

1. Смена аккаунта, возврат через авторизацию и обновление страницы: цель не теряется и не переходит другому пользователю — этап 2.
2. Редактирование старого питомца без изменения даты или фото: сохранение не обнуляет данные — этап 3.
3. Полночь, разные часовые пояса, границы курса: приём относится к правильному локальному дню — этап 4.
4. Двойное нажатие, потеря сети и параллельное редактирование с телефона: не появляются дубли и ложные успехи — этапы 2–5.
5. Клавиатура, увеличенный текст и узкий экран: все действия доступны, фокус виден и поля не перекрыты — этап 7.

## Нумерованные критерии приёмки

1. Новый пользователь проходит оба целевых сценария и пропуск; прежний пользователь не получает обязательный onboarding.
2. Выбранная цель переживает авторизацию и обновление страницы, не протекает между аккаунтами; создание не дублируется.
3. Даты и фото сохраняются, отображаются и редактируются; прежние медицинские данные не теряются.
4. Все девять экранов соответствуют композиции макетов на desktop и в мобильном браузере; существующие разделы доступны.
5. «Напоминания» оформлены обычным текстом с красной подписью просрочки без линии; относительные даты корректны.
6. «Дали»/«Отменить» меняют правильный приём через API; нет ложного успеха при сетевой ошибке.
7. Время курса валидируется, сохраняется и читается повторно; ограничение браузерных уведомлений ясно.
8. Перенос визита и отметка состоявшегося визита работают; Google Календарь получает правильную дату и предлагает сохранить событие.
9. Памятка содержит только нужные актуальные сведения, копируется либо доступна для ручного копирования; PDF для врача работает как прежде.
10. Проверены права, узкие экраны, клавиатура, обязательные тесты и сборка. Есть отчёт с реальными результатами и скриншотами.
